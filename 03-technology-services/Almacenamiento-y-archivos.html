Sección 1 • Fundamentos

Introducción al almacenamiento en AWS

☁️ ¿Por qué almacenamiento en la nube?

  • Elasticidad: Crece o disminuye según la demanda sin comprar discos físicos por adelantado.
  • Durabilidad y disponibilidad: AWS replica automáticamente los datos para evitar pérdidas ante fallos de hardware.
  • Pago por uso: Pagas solo por los GB que almacenas y transfieres.

🏢 Almacenamiento Local vs. Nube

  • Local (On-Premises): Requiere comprar servidores, mantener espacio físico, energía, refrigeración y calcular capacidad máxima años antes.
  • Nube (AWS): Capacidad prácticamente ilimitada bajo demanda, mantenimiento físico gestionado por AWS y acceso global seguro.

Sección 2 • Almacenamiento de Bloques

Amazon EBS (Elastic Block Store)

¿Qué problema resuelve y cómo funciona?

  • Volúmenes persistentes: A diferencia del almacenamiento temporal (Instance Store), los datos en EBS sobreviven aunque detengas o reinicies tu instancia Amazon EC2.
  • Conexión 1 a 1 (generalmente): Se conecta como un disco virtual a una instancia EC2 dentro de la misma Zona de Disponibilidad (AZ).
  • Casos de uso: Discos de arranque del sistema operativo, bases de datos relacionales/NoSQL en EC2 y aplicaciones que requieren baja latencia.
  • Snapshots (Instantáneas): Copias de seguridad incrementales (solo guardan los cambios nuevos) que se almacenan en Amazon S3.

Sección 3 • Almacenamiento de Archivos

Amazon EFS (Elastic File System)

¿Qué es y cuándo utilizarlo?

  • Sistema de archivos compartido: Permite que decenas, cientos o miles de instancias EC2 lean y escriban archivos simultáneamente.
  • Protocolo NFS (Network File System): Diseñado principalmente para cargas de trabajo Linux.
  • Escalabilidad automática (Elástico): Crece y se reduce automáticamente al agregar o borrar archivos; no necesitas reservar tamaño por adelantado.
  • Multi-AZ: Accesible desde instancias EC2 ubicadas en diferentes Zonas de Disponibilidad de una misma Región.
  • Casos de uso: Sistemas de gestión de contenido (CMS como WordPress), directorios compartidos, analítica de datos y contenedores.
Palabras clave examen: Compartido por múltiples EC2 NFS / Linux Escala automáticamente

Sección 4 • Sistemas de Archivos Especializados

Amazon FSx

Amazon FSx permite lanzar y ejecutar sistemas de archivos comerciales y de código abierto totalmente administrados por AWS, sin tener que instalar ni mantener servidores de archivos manualmente.

🪟 Amazon FSx for Windows File Server

  • Almacenamiento de archivos nativo para entornos Windows.
  • Compatible con el protocolo SMB (Server Message Block) y sistema de archivos NTFS.
  • Se integra con Microsoft Active Directory.
  • Uso típico: Carpetas compartidas corporativas y aplicaciones empresariales Windows.

⚡ Amazon FSx for Lustre

  • Sistema de archivos optimizado para computación de alto rendimiento (HPC).
  • Procesamiento ultrarrápido con latencias sub-milisegundo.
  • Se integra directamente con Amazon S3 para procesar datos masivos.
  • Uso típico: Machine Learning, simulaciones financieras, renderizado de video y genómica.

🗄️ Amazon FSx for NetApp ONTAP

Para empresas que ya usan NetApp ONTAP en local y desean migrar a AWS manteniendo sus mismas funciones (deduplicación, snapshots, multiprotocolo NFS/SMB).

🐧 Amazon FSx for OpenZFS

Sistema de archivos administrado basado en el popular sistema de archivos de código abierto OpenZFS, ideal para cargas Linux que requieren alto rendimiento y clonación instantánea.

💡
Idea clave: FSx ofrece sistemas de archivos especializados y administrados (recuerda: Windows/SMB y Lustre/Alto rendimiento).
Sección 5 • Almacenamiento de Objetos

Amazon S3 (Simple Storage Service)

🪣 Conceptos fundamentales

  • Bucket (Contenedor): Carpeta raíz donde guardas tus datos. Su nombre debe ser único a nivel global en todo AWS.
  • Objeto: Cada archivo almacenado (foto, PDF, video, respaldo) + sus metadatos y clave (nombre).
  • Durabilidad del 99.999999999% (11 nueves): AWS replica tus objetos en múltiples instalaciones dentro de una Región.
  • Lifecycle (Ciclo de vida): Reglas automáticas para mover objetos a clases más baratas cuando envejecen o eliminarlos.

Sección 6 • Nube Híbrida

AWS Storage Gateway

🌉 ¿Qué problema resuelve?

Es un servicio de almacenamiento híbrido que conecta las aplicaciones locales (on-premises) de una empresa con el almacenamiento en la nube de AWS, ofreciendo caché local de baja latencia para los archivos más usados.

Ejemplo cotidiano: Un hospital tiene servidores locales que generan miles de radiografías diarias. No quiere quedarse sin espacio en su edificio, así que instala Storage Gateway: los médicos abren exámenes recientes al instante desde la caché local, mientras todo se respalda automáticamente en Amazon S3.

🔌 Los 3 tipos de Gateway (Clave de examen)

1. Amazon S3 File Gateway: Permite que servidores locales guarden archivos mediante protocolos estándar (NFS/SMB) directamente como objetos en Amazon S3.
2. Volume Gateway: Presenta discos de bloques (iSCSI) a servidores locales y respalda sus copias como snapshots de EBS en AWS.
3. Tape Gateway (VTL): Reemplaza las antiguas cintas magnéticas físicas por cintas virtuales almacenadas en S3 y S3 Glacier.
💡
Idea clave: Storage Gateway actúa como un puente híbrido continuo entre la infraestructura local (on-premises) y el almacenamiento de AWS.
Sección 7 • Intercambio Externo de Archivos

AWS Transfer Family

¿Qué es y qué problema resuelve?

  • Servicio totalmente administrado para transferir archivos directamente hacia y desde Amazon S3 o Amazon EFS.
  • Soporta protocolos estándar de la industria: SFTP (SSH File Transfer Protocol), FTPS y FTP (además de AS2 para intercambio empresarial B2B).
  • Cero administración de servidores: Evita instalar, parchar y mantener servidores FTP tradicionales.
  • Casos de uso: Intercambio diario de facturas, nóminas o catálogos con clientes, bancos y proveedores externos que ya usan clientes SFTP.
Palabras clave examen: SFTP / FTPS / FTP Terceros / Proveedores Destino: S3 o EFS

🔍 Trampa clásica de examen: Transfer Family vs. DataSync

Elige AWS Transfer Family cuando:

La pregunta menciona explícitamente los protocolos SFTP, FTPS o FTP para intercambiar archivos con socios comerciales, clientes o sistemas heredados sin cambiar su forma de conectarse.

Elige AWS DataSync cuando:

La pregunta trata sobre migrar o sincronizar grandes volúmenes de datos internos (millones de archivos) de forma rápida y automatizada entre almacenamiento local y AWS.

💡
Idea clave: AWS Transfer Family permite transferir archivos usando protocolos conocidos (SFTP, FTPS, FTP) directamente hacia S3 o EFS sin administrar servidores.
Sección 8 (Parte 1) • Movimiento Masivo de Datos

AWS DataSync y AWS Snow Family

🚀 AWS DataSync (Transferencia por red acelerada)

  • Qué hace: Automatiza y acelera el movimiento de grandes cantidades de datos por internet o AWS Direct Connect entre almacenamiento local y AWS (S3, EFS, FSx), o entre servicios de AWS.
  • Velocidad: Utiliza un protocolo optimizado mucho más rápido que herramientas tradicionales de copia.
  • Casos de uso: Migración única de millones de archivos hacia la nube, replicación periódica para recuperación ante desastres y traslado de datos para análisis.
Transferencia online rápida Automatización y programación

📦 AWS Snow Family (Dispositivos físicos offline)

  • Qué hace: Envío de dispositivos físicos rugerizados a las instalaciones del cliente para copiar terabytes o petabytes de datos y enviarlos de vuelta a AWS por transporte físico.
  • ¿Cuándo usarlos?: Cuando hay ancho de banda limitado, conexiones inestables, zonas remotas (ej. minas, barcos, áreas rurales) o cuando subir los datos por internet tardaría semanas o meses.
  • Referencias del catálogo:
    • AWS Snowcone: Dispositivo pequeño y ultraportátil (terabytes) para edge computing y transferencia.
    • AWS Snowball Edge: Maleta robusta de mayor capacidad (decenas de terabytes) con cómputo y almacenamiento local.
    • Nota histórica (Snowmobile): Fue un camión contenedor diseñado para migraciones de exabytes; hoy es solo una referencia conceptual histórica del catálogo y no un servicio estándar de solicitud general.
💡
Idea clave: Si tienes buena conexión de red usa DataSync; si el ancho de banda es limitado o hay demasiados terabytes para subir por internet, usa dispositivos físicos de AWS Snow Family.
Sección 8 (Parte 2) • Migración de Aplicaciones, BD y Respaldos

MGN, DMS y AWS Backup

🖥️ AWS Application Migration Service (MGN)

  • Propósito: Migrar servidores completos y aplicaciones hacia AWS.
  • Estrategia Lift-and-Shift (Rehost): Replica servidores físicos, virtuales (VMware/Hyper-V) o de otras nubes hacia instancias Amazon EC2 sin tener que reescribir el código de la aplicación.
  • Ventaja: Minimiza el tiempo de inactividad durante el corte final.
Lift-and-Shift Servidores completos

🗄️ AWS Database Migration Service (DMS)

  • Propósito: Migrar bases de datos hacia AWS de forma segura y rápida.
  • Migración homogénea: Mismo motor (ej. Oracle a Oracle, MySQL a MySQL).
  • Migración heterogénea: Distinto motor (ej. Oracle a Amazon Aurora o PostgreSQL, apoyado por Schema Conversion Tool).
  • Alta disponibilidad: La base de datos origen sigue operando mientras DMS replica los cambios continuos.
Homogénea / Heterogénea Mínimo downtime

🛡️ AWS Backup

  • Propósito: Servicio centralizado y automatizado para gestionar copias de seguridad en toda tu cuenta u organización AWS.
  • Recursos compatibles: Volúmenes EBS, sistemas EFS, sistemas FSx, bases de datos RDS, tablas DynamoDB y Storage Gateway.
  • Ventaja: Define políticas únicas (frecuencia, retención y cumplimiento) en un solo panel en lugar de configurar scripts individuales por servicio.
Gestión centralizada Políticas de respaldo
💡
Idea clave: Cada servicio tiene un propósito único: mover archivos (DataSync), transportar datos físicos (Snow), migrar servidores (MGN), migrar bases de datos (DMS) o centralizar respaldos (AWS Backup).
