Módulo 1 · Panorama General

Introducción y Mapa de Redes en AWS

Antes de memorizar servicios, comprende cómo se organizan y comunican los recursos dentro de la nube de AWS.

☁️ ¿Qué significa networking en la nube?

Es la infraestructura virtual que permite que tus servidores, bases de datos y aplicaciones se conecten entre sí, con tu oficina local y con usuarios en Internet de forma segura y controlada por software.

🛡️ ¿Por qué necesitamos redes en AWS?

En AWS compartes infraestructura física con millones de clientes. Las redes virtuales garantizan aislamiento, definen qué es público y qué es privado, y controlan exactamente quién puede entrar o salir.

🔗 ¿Cómo se comunican los recursos?

Mediante direcciones IP privadas (dentro de AWS) o públicas (hacia Internet), guiadas por tablas de enrutamiento y filtradas por firewalls virtuales antes de llegar a cada recurso.

🏰 ¿Qué papel cumple una VPC?

Amazon VPC es tu red privada y aislada dentro de AWS. Es el contenedor lógico donde despliegas tus recursos (como instancias EC2 o bases de datos RDS) con total control sobre sus rangos IP y seguridad.

Módulo 3 · Arquitectura Base

Amazon VPC y su Anatomía

Una Amazon Virtual Private Cloud (VPC) es tu red privada y lógicamente aislada dentro de una Región de AWS. Tú decides su rango IP, cómo se divide y cómo se conecta.

🔒 Red Aislada y Controlada

Ningún otro cliente de AWS puede ver o acceder a tu red por defecto. Tú controlas el tráfico entrante y saliente mediante reglas explícitas.

🌍 Alcance Regional + Multi-AZ

Una VPC vive dentro de una sola Región, pero abarca todas sus Availability Zones (AZ) para lograr alta disponibilidad.

🚦 Subnet Pública vs. Privada

Pública: Tiene ruta directa a un Internet Gateway (ideal para servidores web).
Privada: Sin ruta directa a Internet (ideal para bases de datos).

Módulo 4 · Enrutamiento y Seguridad

Conectividad y Control de Acceso

Domina cómo entra y sale el tráfico de tu VPC y qué capas de seguridad filtran cada paquete.

Simulador de Flujo de Tráfico: Selecciona un escenario

🌐 Internet Gateway (IGW)

Puerta de enlace bidireccional que conecta tu VPC con Internet. Permite que recursos con IP pública reciban y envíen tráfico externo.

🔄 NAT Gateway

Se ubica en una subnet pública y permite que instancias en subnets privadas salgan a Internet (ej. descargar parches) sin permitir conexiones entrantes desde Internet.

🗺️ Route Tables

Conjunto de reglas que indican hacia dónde dirigir el tráfico de red de cada subnet (ej. enviar tráfico 0.0.0.0/0 hacia el IGW o hacia un NAT Gateway).

Firewalls en VPC: Security Groups vs. Network ACLs (NACL)

Ambos controlan tráfico, pero operan a distinto nivel y con comportamientos opuestos respecto al estado de la conexión:

Característica Security Group (SG) Network ACL (NACL)
Nivel donde actúa Nivel de Instancia (ej. EC2) Nivel de Subnet (frontera de la subred)
Tipo de reglas Solo reglas de Permitir (Allow). Todo lo demás se deniega por defecto. Reglas de Permitir (Allow) y Denegar (Deny) explícitas.
Estado (Stateful vs Stateless) Stateful: Si permites tráfico entrante, la respuesta saliente se permite automáticamente. Stateless: El tráfico entrante y saliente se evalúa por separado (debes permitir ambos).
Caso de uso típico Permitir tráfico web HTTPS (puerto 443) hacia tus servidores EC2. Bloquear explícitamente una dirección IP maliciosa antes de que entre a la subnet.
