1. ¿Qué es una red? 1 / 20

Abres tu navegador web y escribes: www.amazon.com. Presionas Enter. ¿Qué ocurre exactamente en ese instante?

💡 El Concepto

Una Red de Computadoras es simplemente dos o más dispositivos conectados entre sí para compartir información y recursos.

📮 La Analogía cotidiana

Es como el sistema postal. Tú redactas una carta (datos), la pones en un sobre con dirección, la echas al buzón y el sistema de correo la entrega a su destino.

☁️ En la nube AWS

AWS es una red gigantesca de centros de datos distribuidos globalmente. Cuando usas AWS, estás creando tus propias "redes virtuales" dentro de su infraestructura física.

2. Paquetes de Datos 2 / 20

La información no se envía como un bloque gigante; se fragmenta en pequeñas piezas llamadas paquetes.

💡 El Concepto

Un Paquete es la unidad básica de información en una red. Contiene tanto los datos reales como la "etiqueta" con la dirección de origen y destino.

📦 La Analogía cotidiana

Si vas a enviar un rompecabezas de 1,000 piezas por correo, no mandas la mesa armada. Separas las piezas en cajas pequeñas numeradas y las envías por separado.

☁️ En la nube AWS

AWS cobra la transferencia de datos principalmente por el volumen de paquetes que salen de sus centros de datos hacia Internet (Data Transfer OUT).

❓ Pregunta para la clase

¿Por qué dividimos los archivos en paquetes en lugar de enviarlos enteros?

💡 IDEA CLAVE PARA EL DOCENTE

"Pregunte a la clase: ¿Qué pasaría si envías un video de 10GB en un solo bloque y se interrumpe la red al 99%? Tendrías que empezar de cero."

🎯 Lo que debes recordar para el examen

AWS mide y cobra el tráfico de red en Gigabytes (GB). El tráfico entrante (Data Transfer IN) suele ser gratis, pero el saliente (OUT) se cobra.

3. Direcciones IP (IPv4) 3 / 20

Para que los paquetes lleguen a su destino, cada dispositivo en una red debe poseer un identificador único: la Dirección IP.

💡 El Concepto

Una IP (Internet Protocol) en IPv4 es un conjunto de 4 números (de 0 a 255) separados por puntos. Ejemplo: 192.168.1.1.

  • IP Privada: Usada dentro de una red interna (casa/empresa). No accesible desde el exterior.
  • IP Pública: Única en todo el mundo, visible en Internet.
🏠 La Analogía cotidiana

Tu IP Privada es como el número de habitación dentro de un hotel. Tu IP Pública es la dirección postal del edificio del hotel en la calle.

🎮 Ejercicio Interactivo: ¿Pública o Privada?

10.0.0.15
☁️ En la nube AWS

Una instancia de servidor EC2 puede tener una IP privada para comunicarse con otros servidores dentro de su red VPC, y una IP pública si necesita ser vista en Internet.

💡 IDEA CLAVE PARA EL DOCENTE

"Evite que los alumnos memoricen matemática hexadecimal o binaria. En Cloud Practitioner basta con saber que la IP privada es interna y la pública es para Internet."

🎯 Lo que debes recordar para el examen

Las instancias en AWS se comunican internamente mediante sus IPs privadas sin costo adicional y con mayor seguridad.

4. DNS - El Traductor de Internet 4 / 20

💡 El Concepto

DNS (Domain Name System) es un servicio que traduce nombres de dominio legibles por humanos a direcciones IP numéricas.

📖 La Analogía cotidiana

☁️ Servicio AWS: Amazon Route 53

Amazon Route 53 es el servicio de DNS administrado y altamente disponible en AWS. Permite registrar dominios y dirigir a los usuarios a la infraestructura adecuada.

5. Puertos y Protocolos 5 / 20

Una IP identifica la máquina (el edificio). El puerto identifica la aplicación o servicio específico dentro de ella (el departamento).

💡 El Concepto

Un Puerto es un número del 0 al 65535 que especifica la puerta de entrada para un servicio particular. Un Protocolo son las reglas del lenguaje que hablan.

🏢 La Analogía cotidiana

La IP es la dirección de un edificio de oficinas. El Puerto 80 es la recepción pública; el Puerto 22 es la puerta trasera de mantenimiento por donde solo entra el personal de servicio.

6. El Router y el Enrutamiento 6 / 20

Los paquetes no viajan en línea recta a ciegas; necesitan un dispositivo inteligente que dirija el tráfico: el Router.

💡 El Concepto

Un Router inspecciona el destino de cada paquete y decide cuál es el mejor camino para enviarlo hacia su destino, consultando una Tabla de Rutas (Route Table).

🚦 La Analogía cotidiana

Es el oficial de tránsito o la aplicación de GPS (Waze) en un cruce de caminos, indicando a cada vehículo qué salida tomar según su destino.

Simulador de Decisión de Ruta:

Tabla de Rutas Simplificada:
Destino 10.0.0.0/16 ➔ Red Local
Destino 0.0.0.0/0 ➔ Internet
☁️ En la nube AWS

En AWS, la Route Table es un recurso configurable donde defines reglas para dirigir el tráfico de tus subredes hacia Internet, hacia otras subredes o hacia una VPN.

💡 IDEA CLAVE PARA EL DOCENTE

"Explique que 0.0.0.0/0 representa 'Cualquier destino en el mundo' (Internet) dentro de una tabla de rutas."

🎯 Lo que debes recordar para el examen

Sin una regla de ruta que apunte hacia un Internet Gateway, los recursos dentro de AWS nunca podrán comunicarse con el exterior.

7. Internet vs. Red Privada 7 / 20

No todos los componentes de un sistema informático deben estar expuestos a todo el mundo.

🌐 Internet (Red Pública)

Pública, global, accesible por cualquier persona del planeta. Ideal para mostrar la portada de tu sitio web a los clientes.

🔒 Red Privada

Aislada, segura, no accesible directamente desde Internet. Ideal para guardar la Base de Datos con los datos sensibles de los clientes.

❓ Escenario Práctico

Estás diseñando la arquitectura para un banco. ¿Dónde colocarías el servidor de la Base de Datos que contiene los saldos de cuentas?

🏨 La Analogía cotidiana

El mostrador del hotel está en el lobby público (Red Pública). La caja fuerte principal del hotel está en una bóveda cerrada en el sótano (Red Privada).

💡 IDEA CLAVE PARA EL DOCENTE

"Inculque la regla de oro de la seguridad en la nube: 'Principio de menor privilegio'. Todo es privado por defecto hasta que sea estrictamente necesario hacerlo público."

🎯 Lo que debes recordar para el examen

Las arquitecturas recomendadas por AWS colocan la capa web en subredes públicas y las bases de datos en subredes privadas.

9. Regiones y Zonas de Disponibilidad 9 / 20

La infraestructura física global de AWS se organiza de forma jerárquica para garantizar la alta disponibilidad.

🌍 Region (Región)

Una ubicación geográfica física en el mundo que contiene varios centros de datos (Ej: us-east-1 en N. Virginia).

🏢 Availability Zone (AZ - Zona de Disponibilidad)

Uno o más centros de datos físicos aislados dentro de una Región, con energía, redes y conectividad independientes.

🏙️ La Analogía cotidiana

  • Subnet Pública: Sus recursos tienen ruta directa hacia Internet.
  • Subnet Privada: Sus recursos NO están expuestos a Internet.

11. Notación CIDR (Tamaño de Red) 11 / 20

Al crear una VPC o Subnet verás notaciones como 10.0.0.0/16 o 10.0.1.0/24. Esto se llama CIDR.

💡 Regla de Oro Simplificada

El número después de la barra (/) indica qué tan grande es la red. ¡Cuanto menor es el número, MÁS IPs tiene la red!

  • /16 ➔ Red Gigante (~65,000 IPs) ➔ Ideal para la VPC entera
  • /24 ➔ Red Mediana (256 IPs) ➔ Ideal para una Subnet
  • /32 ➔ Una ÚNICA IP específica

14. NAT Gateway 14 / 20

¿Cómo puede un servidor privado descargar parches de seguridad de Internet sin volverse accesible a atacantes externos?

☁️ El Concepto

Un NAT Gateway (Network Address Translation) permite que las instancias en una subred privada se conecten a Internet (solo salida), pero evita que Internet inicie conexiones no solicitadas hacia ellas (entrada bloqueada).

🛡️ La Analogía cotidiana

Es un guardaespaldas personal. Sale a buscar las compras que tú pides a la tienda pública, pero no deja que ningún desconocido de la calle entre a tu casa.

💡 IDEA CLAVE PARA EL DOCENTE

🎯 Lo que debes recordar para el examen

Usa NAT Gateway cuando tus servidores de base de datos o backend privado necesiten descargar actualizaciones de software desde Internet de forma segura.

15. Security Group vs. Network ACL (NACL) 15 / 20

AWS ofrece dos capas principales de seguridad tipo firewall en la red. Esta es una pregunta fija de examen.

🛡️ Security Group (SG)

• Firewall virtual a nivel de Instancia/Servidor (ENI).
• Es Stateful (si permites la entrada, la respuesta sale automáticamente).
• Solo soporta reglas de ALLOW (Permitir).
• Evalúa TODAS las reglas antes de decidir.

🧱 Network ACL (NACL)

• Firewall virtual a nivel de Subnet (Subred).
• Es Stateless (debes autorizar explícitamente tanto entrada como salida).
• Soporta reglas de ALLOW y DENY (Permitir y Bloquear).
• Evalúa las reglas en orden numérico estricto.

❓ Caso práctico de Examen

Necesitas bloquear explícitamente una dirección IP maliciosa específica (Ej: 203.0.113.5) para que no acceda a tu red. ¿Qué herramienta usas?

💡 IDEA CLAVE PARA EL DOCENTE

"Analogía rápida: Security Group = El guardia en la puerta de tu departamento personal. NACL = El guardia en la reja principal de la entrada al condominio completo."

🎯 Lo que debes recordar para el examen

Security Group = Nivel Instancia / Stateful / Solo Allow.
Network ACL = Nivel Subnet / Stateless / Allow y Deny.

19. Mitos y Errores Comunes en el Examen 19 / 20

Haz clic en los mitos para revelar la realidad técnica para el examen:

❌ Mito 1: "Una VPC es Internet."
Realidad: Una VPC es una red privada aislada. No tiene acceso a Internet a menos que le adjuntes explícitamente un Internet Gateway y configures las tablas de rutas.
❌ Mito 2: "Security Group y NACL son exactamente lo mismo."
Realidad: SG opera a nivel de instancia y es Stateful; NACL opera a nivel de subnet y es Stateless.
❌ Mito 3: "NAT Gateway permite que usuarios desde Internet se conecten a la Base de Datos."
Realidad: Falso. NAT Gateway es estrictamente de SALIDA (outbound-only). Bloquea toda conexión iniciada desde el exterior.
❌ Mito 4: "Una Region y una Availability Zone son lo mismo."
Realidad: Una Región es una zona geográfica completa. Una AZ es uno o varios data centers independientes dentro de esa región.
