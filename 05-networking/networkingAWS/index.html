Slide 03 — Bloque 1: Fundamentos

¿Qué es Networking?

El arte y la ciencia de interconectar recursos computacionales

Una red de computadoras es simplemente un conjunto de dispositivos conectados entre sí para compartir datos y recursos.

Conceptos Clave
  • Dirección IP: Identificador único de un recurso en la red (ej. 192.168.1.1).
  • DNS: "Directorio telefónico" que traduce nombres (google.com) a IPs.
  • Puertos: "Puertas virtuales" de entrada a un servidor (ej. Puerto 80, 443).
Protocolos Básicos
  • TCP: Conexión confiable y verificada (Web, Email).
  • UDP: Conexión rápida sin verificación (Streaming, Videojuegos).
  • HTTP (80): Tráfico web en texto plano.
  • HTTPS (443): Tráfico web seguro y cifrado.

Slide 06 — Bloque 2: Redes en AWS

Regiones y Zonas de Disponibilidad (AZ)

Dónde reside la infraestructura de red

📍 AWS Region

Una ubicación geográfica en el mundo que contiene múltiples centros de datos aislados y separados geográficamente.

🏢 Availability Zone (AZ)

Uno o más centros de datos físicos discretos con alimentación, refrigeración y conectividad de red independientes.

🎯 Clave para el examen

Una VPC es un recurso regional: pertenece a UNA sola Región, pero se extiende a través de MÚLTIPLES Zonas de Disponibilidad (AZs) dentro de esa región.

Slide 07 — Bloque 3: Amazon VPC

Amazon VPC (Virtual Private Cloud)

Tu red privada y aislada en AWS

¿Qué es Amazon VPC?

Es un servicio que te permite aprovisionar una sección de la nube de AWS aislada lógicamente, donde puedes lanzar recursos de AWS en una red virtual que tú defines.

  • Control total sobre el entorno de red virtual.
  • Selección de rango de direcciones IP (CIDR).
  • Creación de subredes y tablas de enrutamiento.
🏢 Analogía del Edificio

Piensa en la nube de AWS como un rascacielos. Crear una VPC es como alquilar un piso entero privado con su propia cerradura, donde solo entra quien tú autorizas.

Slide 08 — Bloque 3: Amazon VPC

¿Qué recursos viven en una VPC?

Diferenciando recursos VPC vs Globales

✅ Dentro de una VPC
  • Instancias Amazon EC2
  • Bases de datos Amazon RDS
  • Balanceadores de carga (ALB / NLB)
  • Clusters de contenedores (ECS / EKS)
🌐 Servicios fuera de la VPC (Públicos)
  • Amazon S3 (Almacenamiento de objetos)
  • Amazon DynamoDB (Base de datos NoSQL)
  • AWS IAM (Gestión de usuarios)
  • Amazon Route 53 (DNS Global)
Slide 09 — Bloque 4: Direcciones IP

Direcciones IP: La Base del Direccionamiento

Identificando recursos en la red

Cada dispositivo conectado a una red necesita una dirección IP para enviar y recibir paquetes de datos.

Ejemplo IPv4

10.0.0.10

Consta de 4 octetos (32 bits en total) separados por puntos.

IP Privada vs IP Pública
  • IP Privada: Utilizada para comunicación dentro de la VPC. Gratuita y no accesible directamente desde Internet.
  • IP Pública: Accesible desde cualquier lugar de Internet. Requerida para servidores web.
Slide 10 — Bloque 5: CIDR

¿Qué es CIDR?

Classless Inter-Domain Routing — Definición de Rangos IP

CIDR es la notación estándar para definir un rango contiguo de direcciones IP.

Sintaxis CIDR

10.0.0.0 / 16

10.0.0.0: Dirección de red base.

/16: Prefijo que indica cuántos bits están fijos (parte de red).

🏙️ Analogía de la Ciudad

10.0.0.0/16 representa una ciudad entera.

Podemos subdividir esa ciudad en barrios más pequeños: 10.0.1.0/24, 10.0.2.0/24, etc.

Slide 14 — Bloque 6: Subnets

¿Qué es una Subnet (Subred)?

Segmentando tu VPC dentro de una Zona de Disponibilidad

Una Subnet es un rango de direcciones IP en tu VPC. Permite agrupar recursos según sus necesidades de seguridad y conectividad.

Regla Fundamental de Subnets

Cada Subnet reside EXCLUSIVAMENTE dentro de UNA Zona de Disponibilidad (AZ). No puede abarcar múltiples AZs.

📌 IPs Reservadas por AWS

En CADA subnet, AWS reserva automáticamente 5 direcciones IP para fines de gestión interna (red, DNS, gateway, etc.).

Ejemplo: Una subnet /24 tiene 256 IPs totales, pero solo 251 IPs disponibles para tus EC2.

Slide 15 — Bloque 6: Subnets

Public Subnet vs Private Subnet

La distinción más importante en arquitectura AWS

🌐 Public Subnet (Subred Pública)

Contiene una ruta explícita en su Tabla de Enrutamiento hacia un Internet Gateway (IGW).

Uso: Servidores web, Balanceadores de carga de cara al público.

🔒 Private Subnet (Subred Privada)

NO tiene ruta directa hacia un Internet Gateway. Sus recursos no son accesibles desde el exterior.

Uso: Bases de datos, servidores de aplicaciones, microservicios internos.

Slide 16 — Componentes de VPC

Internet Gateway (IGW)

El puente bidireccional entre tu VPC e Internet

¿Qué hace un IGW?
  • Permite que los recursos en subredes públicas se conecten a Internet.
  • Permite que usuarios de Internet inicien conexiones hacia los recursos.
  • Es altamente disponible y redundante por defecto (administrado por AWS).
🌐 Internet
↕
Internet Gateway (IGW)
↕
VPC (Public Subnet)
🎯 Palabras Clave del Examen

Solo se asigna un Internet Gateway por VPC. Es un componente totalmente gestionado por AWS que se escala automáticamente.

Slide 17 — Componentes de VPC

Route Tables (Tablas de Enrutamiento)

El mapa de carreteras de tu red

Una Route Table contiene un conjunto de reglas (rutas) que determinan hacia dónde se dirige el tráfico de red de tu subred.

Ruta por Defecto a Internet

Destination: 0.0.0.0/0

Target: igw-xxxxxxxxx

"Todo el tráfico con destino desconocido, envíalo al Internet Gateway."

Asociación de Subredes
  • Cada subnet DEBE estar asociada a una Route Table.
  • Si no asocias una explícitamente, se asocia automáticamente a la Route Table Principal de la VPC.
Slide 18 — Componentes de VPC

NAT Gateway

Salida segura y unidireccional para recursos privados

¿Para qué sirve?

Permite que recursos en una subred privada se conecten a Internet (ej. para descargar parches o actualizaciones), pero IMPIDE que Internet inicie conexiones hacia ellos.

📌 Ubicación Crucial

El NAT Gateway debe desplegarse SIEMPRE en una Subred Pública y requiere una Elastic IP.

↓
Internet Gateway → 🌐 Internet
Slide 19 — Seguridad en VPC

Security Groups (Grupos de Seguridad)

El firewall virtual a nivel de RECURSO / INSTANCIA

Características Principales
  • Opera a nivel de Instancia EC2 / ENI (no a nivel de subred).
  • Es Stateful (Con estado): Si permites una entrada, la respuesta sale automáticamente.
  • Solo contiene reglas de PERMITIR (Allow). No puedes denegar explícitamente.
  • Por defecto deniega todo el tráfico entrante.
Ejemplo de Reglas Inbound
Puerto Protocolo Origen
80 HTTP 0.0.0.0/0
22 SSH 203.0.113.5/32
Slide 20 — Seguridad en VPC

Network ACL (NACL)

La cortafuegos perimetral a nivel de SUBRED

Características Principales
  • Opera a nivel de Subred. Afecta a TODOS los recursos de esa subnet.
  • Es Stateless (Sin estado): El tráfico de retorno debe ser permitido explícitamente.
  • Soporta reglas de ALLOW y DENY (Permitir y Denegar).
  • Procesa reglas en orden numérico ascendente (100, 200, 300...).
🛡️ Capas de Defensa en Profundidad

1ª Línea de Defensa: NACL (Filtra a la entrada de la Subnet).

2ª Línea de Defensa: Security Group (Filtra a la entrada de la Instancia).

Slide 21 — Seguridad en VPC

Security Group vs Network ACL

La comparación clásica de AWS Certified Cloud Practitioner

Característica Security Group Network ACL (NACL)
Nivel de Operación Instancia / Recursos (ENI) Subred (Subnet)
Estado (State) Stateful (Guarda estado) Stateless (Sin estado)
Reglas de Denegación Solo ALLOW (Permitir) ALLOW y DENY (Denegar)
Evaluación de Reglas Todas las reglas se evalúan En orden numérico (Menor a mayor)
Slide 22 — Conectividad & Servicios

Amazon Route 53

Servicio de DNS Web Altamente Disponible y Escalable

Funciones Clave
  • Registro de Dominios: Compra dominios (ej. miempresa.com).
  • DNS Routing: Traduce nombres de dominio a direcciones IP de AWS o locales.
  • Health Checks: Monitorea la salud de tus recursos para redirigir tráfico si un servidor falla.
💡 Por qué se llama Route 53

Hace referencia al puerto estándar de DNS (Puerto TCP/UDP 53) y al enrutamiento de tráfico (Route).

Slide 23 — Conectividad & Servicios

Elastic Load Balancing (ELB)

Distribución de tráfico entrante para alta disponibilidad

¿Qué es ELB?

Distribuye automáticamente el tráfico de aplicaciones entrante entre múltiples destinos (instancias EC2, contenedores, IPs) en múltiples Zonas de Disponibilidad.

  • Elimina puntos únicos de falla.
  • Se integra con Auto Scaling.
Tipos Principales de ELB
  • ALB (Application Load Balancer): Para tráfico HTTP/HTTPS (Capaz de enrutar por URL).
  • NLB (Network Load Balancer): Alta velocidad, protocolos TCP/UDP (Ultra baja latencia).
Slide 24 — Conectividad & Servicios

Amazon CloudFront

Red de Entrega de Contenido (CDN) Global

¿Cómo funciona?

Utiliza la red mundial de Edge Locations (Ubicaciones periféricas) de AWS para almacenar en caché contenido cerca de los usuarios finales, reduciendo drásticamente la latencia.

🎯 Palabras Clave

Baja latencia, Caché, Edge Locations, Distribución Global de contenidos estáticos y dinámicos.

Usuario Global 👤
↓ (Solicitud rápida)
⚡ Edge Location (Caché)
↓ (Si no está en caché)
Servidor Origen (S3 / EC2)

Slide 26 — Conectividad Híbrida

AWS Site-to-Site VPN

Conexión privada cifrada sobre la Internet pública

VPN vs Direct Connect
  • Site-to-Site VPN: Se configura rápidamente, es económica y transita por la Internet pública encriptando el tráfico (IPsec).
  • Direct Connect: Requiere tiempo de instalación física, privada, sin pasar por Internet.
🎯 Clave para el examen

Si la pregunta pide una solución rápida, económica y cifrada sobre Internet: AWS VPN.
Si pide rendimiento predecible, dedicado y sin Internet: Direct Connect.

Slide 27 — Interconexión VPC

VPC Peering

Conectando dos VPCs directamente entre sí

¿Qué es VPC Peering?

Permite conectar dos VPCs para enrutar tráfico entre ellas de forma privada utilizando direcciones IPv4 o IPv6.

⚠️ Limitación Importante: NO Transitivo

Si VPC A está conectada a VPC B, y VPC B a VPC C, VPC A NO puede comunicarse con VPC C a menos que crees un Peering directo entre A y C.

← Peering →
VPC B

Slide 30 — Caso Práctico

Escenario: Sistema Bancario en AWS

Diseñando una red segura para una aplicación financiera

Requisitos del Banco
  1. Usuarios acceden desde Internet a la web pública.
  2. La base de datos con cuentas debe estar 100% aislada de Internet.
  3. Los servidores de la App privada deben poder descargar parches sin recibir tráfico externo.
Solución de Red AWS
  • Public Subnet: Contiene el Load Balancer y el NAT Gateway.
  • Private Subnet: Contiene servidores de la App y Base de Datos RDS.
  • Security Group: La Base de datos SOLO acepta tráfico desde el Security Group de la App.

Slide 32 — Repaso Anti-Trampas

⚠️ No Confundas Estos Servicios

Evita los errores más comunes de los estudiantes

Internet Gateway vs NAT Gateway

IGW: Permite entrada y salida en subredes públicas.
NAT: Permite SOLO salida a Internet desde subredes privadas.

Security Group vs NACL

SG: A nivel de recurso, Stateful.
NACL: A nivel de Subred, Stateless.

CloudFront vs Route 53

CloudFront: Sirve archivos rápido mediante caché (CDN).
Route 53: Traduce nombres de dominio a IPs (DNS).

VPN vs Direct Connect

VPN: Cifrada sobre Internet pública.
Direct Connect: Conexión física dedicada privada.

Una empresa requiere que sus instancias EC2 ubicadas en una subred privada descarguen actualizaciones de software desde Internet, pero no debe permitir que usuarios externos inicien conexiones hacia ellas. ¿Qué servicio de AWS se debe utilizar?
