Módulo 1 de 7 • Fundamentos Cloud

Introducción a Serverless y Servicios Administrados

Ejecutar aplicaciones en la nube significa usar recursos de cómputo bajo demanda a través de internet, eligiendo cuánta infraestructura deseas administrar.

Administrar Servidores (Ej. Amazon EC2)

Alquilas servidores virtuales y tienes control total sobre ellos, pero también la responsabilidad operativa.

  • Tú eliges el sistema operativo y su tamaño.
  • Tú aplicas actualizaciones y parches de seguridad.
  • Pagas por el servidor mientras esté encendido, incluso sin tráfico.

Servicios Administrados y Serverless

Delegas la gestión de los servidores a AWS para concentrarte únicamente en tu aplicación y lógica de negocio.

  • AWS aprovisiona, parchea y mantiene los servidores.
  • Escalabilidad automática según la demanda real.
  • En Serverless, solo pagas cuando el código se ejecuta.
Analogía cotidiana: Auto propio vs. Taxi / App de transporte

Administrar servidores es como comprar un auto: debes cargarle combustible, cambiarle el aceite y pagar seguro aunque esté estacionado. Serverless es como pedir un viaje por aplicación: los autos (servidores) existen, pero tú no los mantienes; solo pides el viaje cuando lo necesitas y pagas únicamente por el trayecto recorrido.

¿Qué significa realmente "Serverless" (Sin servidor)?

Serverless NO significa que no existan servidores físicos. Significa que los servidores son completamente invisibles para ti: AWS administra el sistema operativo, la capacidad, la disponibilidad y el mantenimiento subyacente. Tú solo entregas tu código o configuración.

Módulo 2 de 7 • Cómputo Serverless

AWS Lambda

Servicio de cómputo serverless que permite ejecutar código en respuesta a eventos sin aprovisionar ni administrar servidores.

Basado en Eventos

El código vive en una función Lambda y permanece inactivo hasta que ocurre un evento mediante un desencadenador (trigger).

Pago por Uso Real

Pagas únicamente por la cantidad de solicitudes y el tiempo exacto (en milisegundos) que tu código está ejecutándose. Cero costo en reposo.

Escalabilidad Automática

Si llegan 1 o 10.000 eventos al mismo tiempo, AWS Lambda ejecuta copias paralelas de tu función automáticamente sin intervención manual.

Módulo 3 de 7 • Integración de Aplicaciones

APIs y Amazon API Gateway

Cómo se comunican las aplicaciones entre sí y cómo AWS ofrece una puerta de entrada administrada y segura.

Analogía cotidiana: El mesero de un restaurante

Tú (el Cliente) estás en la mesa y quieres comida de la cocina (el Servidor/Backend), pero no entras directo a cocinar. Le pides al mesero (la API) lo que deseas usando el menú; el mesero lleva tu solicitud a la cocina y te trae la respuesta (tu plato).

¿Qué es una API?

Es una interfaz que permite que dos aplicaciones distintas se comuniquen e intercambien datos siguiendo reglas claras, sin necesidad de conocer cómo está programada la otra.

Solicitud y Respuesta HTTP

La aplicación cliente envía una solicitud (Request) pidiendo datos o enviando información por internet, y el servidor devuelve una respuesta (Response) con el resultado.

¿Qué es un Endpoint?

Es la dirección URL específica donde una API recibe las solicitudes (por ejemplo: api.mitienda.com/pedidos).

¿Qué es y qué problema resuelve Amazon API Gateway?

Cuando tienes muchas funciones o microservicios, exponerlos directamente es inseguro y difícil de controlar. Amazon API Gateway es un servicio totalmente administrado que actúa como la "puerta principal" para crear, publicar, mantener, monitorear y proteger APIs a cualquier escala.

HTTP API

Diseñada para construir APIs rápidas y de menor costo conectadas directamente a servicios como AWS Lambda o backends HTTP.

REST API

Ofrece control completo sobre solicitudes y respuestas, además de funciones avanzadas como claves de API, límites de tráfico y caché.

Módulo 4 de 7 • Orquestación de Flujos

AWS Step Functions

Servicio de orquestación serverless que coordina múltiples servicios de AWS en flujos de trabajo visuales paso a paso.

¿Qué problema resuelve?

Cuando un proceso de negocio requiere varios pasos consecutivos (validar, cobrar, actualizar stock, notificar), conectar todo dentro de una sola función gigante es difícil de mantener y propenso a fallos. Step Functions divide el proceso en pasos claros y ordenados.

Conceptos clave: Flujo, Estados y Pasos

  • Flujo de trabajo (Workflow): El mapa completo del proceso de principio a fin.
  • Estados (States): Cada paso individual (ejecutar una tarea, tomar una decisión, esperar o manejar un error).
  • Manejo de errores: Si un paso falla, puede reintentar automáticamente o ejecutar un plan alternativo sin romper todo el sistema.

Módulo 5 de 7 • Portabilidad y Orquestación

Contenedores en AWS

Empaqueta tu aplicación junto con todo lo que necesita para funcionar de manera idéntica en cualquier entorno.

¿Qué es un Contenedor y qué es Docker?

Un contenedor es un paquete ligero y estandarizado que incluye el código de una aplicación junto con sus librerías y dependencias. Esto resuelve el clásico problema de "en mi computadora sí funciona".

Docker es la plataforma estándar más utilizada para crear, empaquetar y ejecutar contenedores a partir de una plantilla llamada imagen.

Contenedor vs. Máquina Virtual (VM)

  • Máquina Virtual (ej. EC2): Virtualiza el hardware completo e incluye su propio sistema operativo completo. Pesa gigabytes y tarda minutos en iniciar.
  • Contenedor: Comparte el núcleo (kernel) del sistema operativo anfitrión y solo empaca la aplicación y sus dependencias. Pesa megabytes y arranca en segundos.

Servicios principales de contenedores en AWS

ECR

Amazon ECR

Elastic Container Registry: Almacén privado y seguro para guardar, administrar y compartir imágenes de contenedores Docker.

ECS

Amazon ECS

Elastic Container Service: Orquestador nativo de AWS sencillo y altamente integrado para ejecutar y escalar contenedores.

EKS

Amazon EKS

Elastic Kubernetes Service: Servicio administrado para ejecutar Kubernetes en AWS sin tener que instalar su plano de control.

Fargate

AWS Fargate

Cómputo Serverless para contenedores: Ejecuta contenedores en ECS o EKS sin tener que crear ni administrar servidores EC2.
