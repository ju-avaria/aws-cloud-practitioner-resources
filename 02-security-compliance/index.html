🛡️ ¿Qué significa seguridad en la nube?
Protección integral de activos digitales

Seguridad en AWS consiste en proteger activamente los siguientes componentes:

💾 Datos

Archivos en S3, bases de datos y backups.

👤 Identidades

Usuarios, credenciales y roles de servicio.

💻 Aplicaciones

Código ejecutable, APIs y microservicios.

🏗️ Infraestructura

Instancias EC2, almacenamiento y hardware.

🌐 Redes

Subredes, routers y firewalls virtuales.

⚙️ Configuraciones

Reglas de cumplimiento y buenas prácticas.

📐 Los tres objetivos de seguridad (Tríada CIA)
Pilares de la seguridad de la información

Confidencialidad

"Solo personas autorizadas acceden."

Garantizar que la información privada no sea vista por terceros. Ex: Cifrado en Amazon S3.

Integridad

"La información no se altera sin permiso."

Garantizar que los datos permanezcan exactos y no sean modificados. Ex: Versionado en S3.

Disponibilidad

"Sistemas listos cuando se necesitan."

Garantizar acceso constante a la infraestructura. Ex: Multi-AZ en RDS y Auto Scaling.

💡 Ejemplo práctico: Amenazas reales
Escenario: Una empresa almacena información de clientes en AWS

❌ Filtración de Datos

Un usuario no autorizado accede a datos bancarios guardados en un bucket público.

Falla de Confidencialidad

❌ Alteración no Autorizada

Un script malicioso modifica los saldos de los clientes en la base de datos.

Falla de Integridad

❌ Caída por Ataque DDoS

Un ataque de denegación de servicio bloquea el acceso a la aplicación web.

Falla de Disponibilidad

🧅 Seguridad en Capas (Defense in Depth)
La seguridad no depende de un solo mecanismo

Si una capa falla, la siguiente debe detener la amenaza:

1. Identidad & MFA
2. Permisos y Políticas (IAM)
3. Perímetro de Red (Security Groups / NACL / WAF)
4. Protección de Aplicaciones
5. Cifrado de Datos (At Rest / In Transit)
6. Monitoreo, Auditoría y Respuesta
🔄 El Ciclo Conceptual de Seguridad
Un marco estructurado para organizar las prácticas de seguridad

2. DETECTAR

🛡️ Etapa 1: PREVENIR
"¿Qué hacemos antes de que ocurra un incidente?"

Least Privilege

Permisos mínimos requeridos para cada tarea.

Security Groups & NACLs

Firewalls perimetrales a nivel de recurso y subred.

AWS WAF & Shield

Filtro de exploits web y protección DDoS.

AWS KMS

Cifrado de datos en reposo.

🔍 Etapa 2: DETECTAR
"Identificar actividades, vulnerabilidades y configuraciones"

AWS CloudTrail

Registro y auditoría de llamadas API.

Detección inteligente de amenazas con ML.

Amazon Inspector

Evaluación de vulnerabilidades de software.

Auditoría de configuraciones de recursos y reglas.

🚨 Etapa 3: RESPONDER
"Aislar, investigar y corregir la amenaza"

Flujo de Respuesta:

Detectar ➔ Investigar ➔ Contener ➔ Actuar

  • Revocar accesos: Deshabilitar credenciales IAM comprometidas.
  • Aislar recursos: Cambiar Security Group de una EC2 para desconectarla de la red.
  • Investigar: Usar Amazon Detective para analizar la causa raíz.

"Restaurar la operación y aprender del incidente"

Lecciones Aprendidas

🤝 Modelo de Responsabilidad Compartida
AWS + Cliente = Seguridad Completa

En AWS, la seguridad es una responsabilidad compartida.

La frontera exacta de responsabilidad depende del servicio utilizado.

🏢 AWS: Security OF the Cloud
Seguridad DE la nube

AWS es responsable de proteger la infraestructura física e infraestructura base:

Centros de Datos

Seguridad física, guardias, control de acceso e instalaciones.

Hardware

Servidores físicos, racks y unidades de almacenamiento.

Infraestructura Global

Regiones, Availability Zones (AZ) y Edge Locations.

Virtualización Base

Hipervisores y redes físicas subyacentes.

👤 Cliente: Security IN the Cloud
Seguridad EN la nube

El cliente es responsable de todo lo que coloca y configura en la nube:

Datos del Cliente

Cifrado y clasificación de la información.

Gestión IAM

Usuarios, permisos, políticas y habilitación de MFA.

Sistemas Operativos

Parches de SO en instancias EC2 (IaaS).

Configuración de Red

Reglas de firewall en Security Groups y NACLs.

⚖️ La responsabilidad depende del servicio
Comparación de abstracción

IaaS (ej. Amazon EC2)

Mayor responsabilidad del cliente. El cliente debe actualizar el Sistema Operativo, parches de seguridad y aplicaciones.

PaaS / Administrado (ej. RDS)

AWS administra el SO. AWS instala parches del motor y SO. El cliente configura tablas, accesos y cifrado.

Serverless / SaaS (ej. S3)

Máxima abstracción. AWS gestiona la infraestructura física y lógica. El cliente administra accesos y datos.

Clasifica las tareas según corresponda

🔑 ¿Quién puede acceder? (AWS IAM)
AWS Identity and Access Management

IAM gestiona de forma centralizada la autenticación y autorización en AWS.

Flujo de Evaluación de Acceso:

Identity ➔ Authentication ➔ Authorization ➔ Resource

⚖️ Authentication vs Authorization
Diferencia conceptual fundamental

Authentication (Autenticación)

¿Quién eres?

Proceso de verificar la identidad del usuario o servicio.

Ejemplo: Iniciar sesión con usuario, contraseña y token MFA.

Authorization (Autorización)

¿Qué puedes hacer?

Evaluación de permisos concedidos sobre los recursos.

Ejemplo: Permitir que Juan ejecute s3:GetObject en un bucket.

🧩 Componentes Principales de IAM
Entidades y controles de acceso

👤 Users

Identidades persistentes para personas o aplicaciones.

👥 Groups

Colección de usuarios para asignación masiva de permisos.

🎭 Roles

Identidades asumidas temporalmente por servicios o personas.

📜 Policies

Documentos JSON que definen permisos (Allow/Deny).

👤 IAM User
Identidad individual permanente

Un IAM User representa a una persona o sistema específico que interactúa de manera continua con AWS.

  • Acceso a Consola: Usuario y Contraseña.
  • Acceso por CLI / SDK: Access Key ID y Secret Access Key.
👥 IAM Group
Administración simplificada de usuarios

Un IAM Group agrupa múltiples usuarios para otorgarles permisos idénticos simultáneamente.

Grupo: Developers ➔ Política Adjunta: AmazonS3ReadOnlyAccess

Todos los miembros heredan el acceso automáticamente.

🎭 IAM Role
Credenciales temporales seguras

Un IAM Role no utiliza credenciales fijas; se asume temporalmente.

Patrón de Seguridad Clave:

Instancia EC2 ➔ Asume IAM Role ➔ Accede a Amazon S3 sin guardar claves en disco

⚖️ IAM User vs IAM Role
Comparación práctica
Característica IAM User IAM Role
Credenciales Permanentes (Password / Access Keys) Temporales (Expiran automáticamente)
Uso recomendado Personas humanas / Desarrolladores Servicios AWS (EC2, Lambda) / Cuentas cruzadas
Mantenimiento Requiere rotación manual de claves Sin claves que gestionar o almacenar
🎯 Principio de Mínimo Privilegio (Least Privilege)
Otorgar solo los permisos indispensables

❌ Permisos Excesivos

Otorgar AdministratorAccess a un desarrollador que solo necesita leer archivos en un bucket S3.

✅ Permisos Necesarios

Crear una política personalizada que conceda únicamente s3:GetObject sobre el bucket de desarrollo.

🔐 Autenticación Multifactor (MFA)
Segunda capa de verificación de identidad

Password (Algo que sabes) + Token MFA (Algo que tienes) = Acceso Protegido

⚠️ REGLA DE EXAMEN: Es obligatorio habilitar MFA en la cuenta Root de AWS.

🏢 AWS Organizations
Gestión centralizada de múltiples cuentas de AWS

Management Account

Cuenta administradora central que consolida la facturación.

Member Accounts

Cuentas individuales agrupadas por funciones de negocio.

Organizational Units (OUs)

Estructura jerárquica para agrupar cuentas (ej. Prod, Dev).

🛡️ Service Control Policies (SCP)
Frontera de permisos máximos a nivel de cuenta

⚠️ REGLA DE EXAMEN CRÍTICA:

Una SCP NO concede permisos por sí misma. Una SCP establece el límite máximo de permisos posibles para las cuentas miembro de una organización.

Permisos Efectivos = Permisos otorgados por IAM LIMITADOS POR la SCP de la cuenta.

🌐 AWS IAM Identity Center
Acceso Single Sign-On (SSO) centralizado

Permite administrar el acceso SSO centralizado a múltiples cuentas de AWS y aplicaciones empresariales (ej. Microsoft 365, Salesforce) utilizando un único conjunto de credenciales.

💡 Escenario de Examen: Gobierno Multicuenta
Evaluación de acceso centralizado

Escenario: Una organización con 50 cuentas AWS desea restringir de forma absoluta que ninguna cuenta pueda eliminar registros de CloudTrail, incluso si el usuario es administrador de esa cuenta local.

📦 Protección de Datos y Cifrado
Estados principales de los datos

🔒 Data at Rest (En Reposo)

Datos almacenados en discos EBS, buckets S3 o bases de datos RDS.

🚀 Data in Transit (En Tránsito)

Datos viajando a través de la red entre usuarios y servidores.

🔒 Encryption at Rest (En Reposo)
Protección de almacenamiento de información

Datos en Texto Plano ➔ [ Clave Criptográfica KMS ] ➔ Datos Cifrados Ilegibles en Disco

🚀 Encryption in Transit (En Tránsito)
Protección de la comunicación en red

Cliente / Navegador ➔ [ Canal Seguro TLS / HTTPS ] ➔ Servicio AWS

Evita la lectura o manipulación de datos en tránsito por terceros en la red.

🔑 AWS Key Management Service (KMS)
Gestión centralizada de claves criptográficas

Servicio administrado que permite crear, controlar y gestionar las claves criptográficas para cifrar datos en reposo.

Integración nativa con: S3, EBS, RDS, DynamoDB y Secrets Manager.

⚖️ Comparación: Cifrado de Datos
Resumen conceptual de almacenamiento vs transmisión
Estado ¿Dónde aplica? Tecnología principal
Data at Rest Volúmenes EBS, Buckets S3, Bases RDS AWS KMS / Algoritmo AES-256
Data in Transit Red pública / Conexiones entre servicios TLS / HTTPS / Certificados ACM
🧱 Security Groups
Firewall virtual a nivel de recurso

Características Clave para Examen:

  • Asociado directamente a la Instancia (ej. EC2).
  • Es Stateful (con estado): El tráfico de respuesta sale automáticamente.
  • Solo permite reglas de ALLOW (Permitir). No existen reglas Deny.
🚧 Network ACL (NACL)
Firewall perimetral a nivel de subred

Características Clave para Examen:

  • Asociado a nivel de Subred (Subnet).
  • Es Stateless (sin estado): Requiere reglas explícitas de entrada y salida.
  • Soporta reglas de ALLOW y DENEGAR (Deny).
⚖️ Security Group vs Network ACL
Tabla comparativa de examen
Característica Security Group Network ACL (NACL)
Nivel de aplicación Recurso / Instancia (EC2) Subred (Subnet)
Estado (State) Stateful (con estado) Stateless (sin estado)
Tipos de Reglas Solo ALLOW ALLOW y DENY
🌐 AWS WAF (Web Application Firewall)
Protección en la Capa de Aplicación (Capa 7)

Protege aplicaciones web filtrando el tráfico HTTP/HTTPS.

Ataques que mitiga:

  • SQL Injection (SQLi)
  • Cross-Site Scripting (XSS)
🛡️ AWS Shield
Protección contra ataques DDoS

Shield Standard

Gratuito y activado por defecto para todas las cuentas en Capa 3/4.

Shield Advanced

Protección avanzada de pago con soporte 24/7 y respuesta a DDoS masivos.

⚖️ AWS WAF vs AWS Shield
Diferenciación de protección de red

AWS WAF

Protege contra ataques de aplicaciones web en Capa 7 (SQLi, XSS).

AWS Shield

Protege contra ataques de denegación de servicio distribuido (DDoS) en Capa 3/4.

⚙️ ¿Está correctamente configurado?
Evaluación continua y gestión de reglas de cumplimiento

La seguridad no consiste únicamente en detener ataques activos.

Se requiere evaluar configuraciones, registrar cambios en el tiempo y verificar si los recursos cumplen con las reglas internas de la empresa.

📜 AWS Config
Auditoría y evaluación de configuraciones de recursos

Palabras clave de examen:

Resource Configuration / Configuration History / Compliance Rules / Compliant vs Noncompliant

Registra los cambios de configuración de los recursos de AWS y los evalúa de forma continua frente a reglas predefinidas.

⚖️ AWS Config vs AWS CloudTrail
Diferencia crítica en auditoría

AWS Config

¿Cómo está configurado el recurso?

Evalúa el estado del recurso y sus cambios (ej. si un bucket S3 pasó a ser público).

AWS CloudTrail

¿Qué actividad / llamada API ocurrió?

Registra la acción del usuario (ej. quién ejecutó la API para hacer el bucket público).

🔄 AWS Config en el Ciclo de Seguridad
Uso en Prevenir y Detectar

Configuración Incorrecta ➔ AWS Config Rule ➔ Estado: NONCOMPLIANT ➔ Alerta y Corrección

👁️ ¿Cómo sabemos qué está ocurriendo?
Detección, Monitoreo y Auditoría

Monitor ➔ Log ➔ Audit ➔ Detect ➔ Investigate

📜 AWS CloudTrail
Auditoría de actividad y llamadas API

Palabras clave de examen:

API Activity / User Activity / Audit Log / Account History

Registra las acciones realizadas por usuarios, roles o servicios en la cuenta. Responde a: ¿Quién hizo qué?

📊 Amazon CloudWatch
Monitoreo de rendimiento y métricas

Palabras clave de examen:

Metrics / Logs / Alarms / Observability

Recopila métricas operativas (uso de CPU, red) y configura alarmas para alertas de rendimiento.

🛡️ Amazon GuardDuty
Detección inteligente de amenazas

Palabras clave de examen:

Threat Detection / Machine Learning / Suspicious Activity

Analiza continuamente registros de red y CloudTrail para identificar comportamientos maliciosos o anómalos.

🔍 Amazon Inspector
Evaluación de vulnerabilidades de software

Palabras clave de examen:

Vulnerability Assessment / EC2 Scans / Software Flaws

Escanea automáticamente cargas de trabajo EC2 y contenedores en busca de vulnerabilidades de software conocidas.

🎯 AWS Security Hub
Centralización de hallazgos de seguridad

Consolida los hallazgos de GuardDuty, Inspector, Macie y AWS Config en un único panel centralizado para gestionar el cumplimiento.

🔎 Amazon Detective
Investigación de posibles incidentes

Analiza e investiga las causas raíz de eventos de seguridad utilizando gráficos de visualización de datos de la cuenta.

Flujo integrado

📋 Caso Práctico 1: Detección de Amenazas

Escenario: Una empresa requiere analizar llamadas API inusuales y posibles credenciales comprometidas utilizando Machine Learning.

¡Correcto! Amazon GuardDuty utiliza ML para detectar amenazas. Palabra clave: Threat Detection / ML.
📋 Caso Práctico 2: Auditoría e Informes

Escenario: Un auditor de seguridad necesita descargar los reportes de cumplimiento SOC 2 de la infraestructura de AWS.

¡Correcto! AWS Artifact es el portal para reportes de cumplimiento normativo. Palabra clave: Compliance Reports.
📋 Caso Práctico 3: Asignación de Permisos

Escenario: Una aplicación que corre en una instancia EC2 necesita escribir archivos en Amazon S3 de forma segura.

¡Correcto! IAM Roles otorgan credenciales temporales a servicios de AWS. Palabra clave: Temporary Credentials / IAM Role.
📋 Caso Práctico 4: Ataques DDoS

Escenario: Se requiere proteger la aplicación web contra ataques masivos de denegación de servicio (DDoS) en la capa de red.

¡Correcto! AWS Shield mitiga ataques DDoS. Palabra clave: DDoS Protection.
📋 Caso Práctico 5: Evaluación de Vulnerabilidades

Escenario: Una empresa necesita escanear sus instancias EC2 para identificar paquetes de software con vulnerabilidades conocidas.

¡Correcto! Amazon Inspector realiza análisis de vulnerabilidades en cargas de trabajo. Palabra clave: Vulnerability Assessment.
📋 Caso Práctico 6: Evaluación de Reglas de Configuración

Escenario: Se desea evaluar continuamente si los volúmenes EBS creados en la cuenta tienen activado el cifrado frente a una regla establecida.

¡Correcto! AWS Config evalúa si los recursos cumplen con las reglas de configuración. Palabra clave: Configuration Rules / Compliance.
📋 Caso Práctico 7: Recomendaciones Generales

Escenario: Se requiere un análisis general del entorno para obtener recomendaciones sobre límites de servicio, costos y seguridad básica.

¡Correcto! AWS Trusted Advisor otorga recomendaciones sobre buenas prácticas en 5 pilares. Palabra clave: Recommendations.
📋 Caso Práctico 8: Registro de Actividad de Usuarios

Escenario: Se necesita determinar cuál usuario eliminó un bucket S3 específico a las 3:00 AM.

¡Correcto! AWS CloudTrail audita e identifica la actividad y llamadas a la API. Palabra clave: API Activity / Audit.
