Slide 03 — Fundamentos

Amazon S3 en una Frase

Almacenamiento de objetos diseñado para cualquier cantidad de datos desde cualquier lugar

¿Qué es Amazon S3?

Amazon S3 es un servicio de almacenamiento de objetos que ofrece escalabilidad, disponibilidad de datos, seguridad y rendimiento líderes en la industria.

🎯 Clave de Examen

S3 es almacenamiento de objetos (archivos), NO es almacenamiento de bloques (EBS) ni un sistema de archivos tradicional (EFS).

📱 Aplicación / Cliente
↓ HTTPS API ↓
📦 Amazon S3
↓ Almacena ↓
Imágenes, Videos, Docs, Backups, Datasets, Logs
Slide 04 — Cambiando el Modelo Mental

¿Por qué existe Amazon S3?

Evolución de servidores tradicionales a almacenamiento de objetos sin límites

❌ Servidor Tradicional (Discos)
  • Capacidad limitada del disco local.
  • Mantenimiento y aprovisionamiento manual.
  • Riesgo de fallo de hardware y pérdida de datos.
  • Escalar requiere cambiar o agregar discos físicos.
✅ Almacenamiento en Amazon S3
  • Capacidad virtualmente ilimitada.
  • Totalmente administrado (sin servidores que gestionar).
  • Diseñado para 99.999999999% (11 nueves) de durabilidad.
  • Pagas solo por lo que usas exactamente.
Slide 05 — Conceptos Núcleo

Modelo Mental: Account ➔ Bucket ➔ Object ➔ Key

Jerarquía lógica del almacenamiento de objetos

Componentes Principales
  • Bucket: Contenedor lógico globalmente único en la cuenta AWS donde se guardan los objetos.
  • Object: El archivo real alojado dentro del bucket.
  • Key: Identificador único (ruta lógica) dentro del bucket.

Ejemplo de Identificación:

Bucket: mi-empresa-bucket

Key: imagenes/2026/perfil.jpg

URL Completa:
https://mi-empresa-bucket.s3.amazonaws.com/imagenes/2026/perfil.jpg

Slide 07 — Profundización

Anatomía de un Objeto en S3

Un objeto no es solo un archivo de datos

Componentes de un Objeto
  • Data (Value): La secuencia de bytes del archivo en sí.
  • Key (Name): Identificador de nombre completo.
  • Metadata: Paquetes clave-valor sobre el objeto (ej. Content-Type: image/png).
  • Tags: Etiquetas de clasificación para costos o seguridad.
  • Version ID: Identificador único cuando Versioning está activo.

Object Payload Breakdown: 

Object {
  Key: "docs/contrato.pdf",
  Data: [Binary Data Stream],
  Metadata: {
    "Content-Type": "application/pdf",
    "Author": "Legal Dept"
  },
  Tags: { "env": "production" },
  VersionId: "v1.0.3"
}

Slide 10 — Storage Classes

S3 Intelligent-Tiering

Optimización automática sin impacto operativo ni penalizaciones por recuperación.

¿Cómo funciona?

Monitorea automáticamente los patrones de acceso a los objetos. Si un objeto no se accede por 30 días seguidos, lo mueve al nivel Infrequent Access. Si se vuelve a acceder, regresa al nivel Frequent Access.

🎯 Cuándo Elegir Intelligent-Tiering

Cuando los patrones de acceso son desconocidos, impredecibles o cambiantes. Sin tarifas de recuperación de datos.

📦 Objeto Subido ➔ Frequent Access Tier
↓ (Sin accesos por 30 días) ↓
📉 Infrequent Access Tier (Ahorro instantáneo)
↓ (Acceso repentino detectado) ↓
⚡ Regresa a Frequent Access Tier sin interrupción
Slide 11 — Storage Classes

Amazon S3 Glacier: ¡No es solo "Backup"!

Diferenciando las 3 variantes de Glacier según la velocidad de recuperación

Glacier Instant Retrieval

Recuperación en **milisegundos**. Para archivos archivados pero que deben estar disponibles inmediatamente cuando se solicitan.

Glacier Flexible Retrieval

Recuperación en minutos a horas (Expedited: 1-5 min, Standard: 3-5 hrs, Bulk: 5-12 hrs). Para copias históricas.

Glacier Deep Archive

Recuperación en 12 a 48 horas. La opción de menor costo en todo AWS para retención regulatoria de largo plazo.

Slide 13 — Automatización

S3 Lifecycle Policies (Ciclo de Vida)

Automatizando transiciones y expiración de objetos para reducir costos

Acciones de Lifecycle
  • Transition Actions: Mueven automáticamente objetos a clases más económicas según la antigüedad.
  • Expiration Actions: Eliminan permanentemente objetos expirados.
🎯 Palabra Clave para Examen

Palabras como "Automate cost reduction", "Delete logs after 90 days", "Transition after 30 days" apuntan a S3 Lifecycle Rules.

S3 Standard ➔ (30 Días) ➔ S3 Standard-IA ➔ (90 Días) ➔ Glacier Flexible ➔ (365 Días) ➔ Delete ❌

Slide 15 — Protección de Datos

S3 Versioning (Control de Versiones)

Mantiene múltiples variantes de un mismo objeto dentro del bucket

Beneficios Principales
  • Protección contra sobrescrituras o eliminaciones accidentales.
  • Permite recuperar versiones antiguas de un archivo.
  • Un borrado ordinario solo coloca un Delete Marker que se puede revertir.
⚠️ Impacto en Costos

Cada versión almacena el archivo completo, lo que incrementa el espacio utilizado y los costos de almacenamiento si no se combina con Lifecycle.

Slide 16 — Optimización Avanzada

Versioning + Lifecycle Policies

Gestión diferenciada entre Versiones Actuales y No Actuales

Current vs Noncurrent Versions

S3 Lifecycle permite aplicar reglas específicas para **Noncurrent Versions** (versiones antiguas):

  • Mover versiones antiguas a Glacier tras 30 días.
  • Eliminar versiones antiguas tras 90 días mientras se conserva la versión actual activa.

Slide 17 — Disponibilidad Global

S3 Replication (CRR y SRR)

Copia automática e asíncrona de objetos entre buckets

Tipos de Replicación
  • Cross-Region Replication (CRR): Copia objetos a una Región AWS distinta para cumplir con desastres o latencia.
  • Same-Region Replication (SRR): Copia objetos entre buckets de la misma Región AWS.
🎯 Requisito Obligatorio

Para activar Replicación en S3, **Versioning DEBE estar activado** en ambos buckets (origen y destino).

Region A (us-east-1) ➔ Bucket Origen
↓ Replicación CRR (Asíncrona) ↓
Region B (eu-west-1) ➔ Bucket Destino
Slide 18 — Seguridad

Tríada de Seguridad en Amazon S3

Autenticación, Autorización y Cifrado de Datos

1. IAM Policies

Políticas basadas en **identidades** (Usuarios, Grupos, Roles) para especificar qué acciones pueden realizar sobre S3.

2. Bucket Policies

Políticas basadas en el **recurso** adjuntas directamente al bucket de S3 en formato JSON.

3. Encryption

Protección de datos en tránsito (HTTPS) y en reposo (SSE-S3, SSE-KMS).

Slide 19 — Seguridad

IAM Policies vs Bucket Policies

¿Cuándo usar cada mecanismo de permisos?

IAM Policy (Identity-Based)

Se adjunta a un usuario/rol. Responde: *"¿A qué recursos de S3 tiene acceso este usuario?"* 

User: Ana ➔ Allow s3:GetObject on arn:aws:s3:::bucket/*
Bucket Policy (Resource-Based)

Se adjunta al Bucket S3. Responde: *"¿Quién tiene permitido o denegado el acceso a mi bucket?"* 

Bucket: mi-bucket ➔ Deny Anonymous access if not HTTPS
Slide 20 — Seguridad

S3 Block Public Access

Capa centralizada de protección contra fugas de datos involuntarias

Capa de Protección Global

Funciona como un interruptor maestro a nivel de cuenta o de bucket que invalida cualquier permiso público accidental otorgado mediante Bucket Policies o ACLs.

🎯 Ajuste Predeterminado en AWS

Por defecto, **S3 Block Public Access está ACTIVADO** en todos los buckets nuevos creados en AWS.

Slide 21 — Seguridad

Cifrado en Amazon S3 (Encryption)

Protección de datos en Reposo y en Tránsito

Encryption at Rest (En Reposo)
  • SSE-S3: Claves gestionadas completamente por S3 (cifrado predeterminado).
  • SSE-KMS: Claves gestionadas mediante AWS Key Management Service (KMS) con auditoría.
  • SSE-C: Claves provistas por el cliente.
Encryption in Transit (En Tránsito)

Los datos se cifran durante la transmisión entre el cliente y S3 utilizando protocolos seguros **HTTPS / TLS**

🎯 Concepto Clave

Cifrado = Confidencialidad de datos. Autorización (IAM) = Permiso de acceso.

Slide 22 — Cumplimiento

S3 Object Lock y Modelo WORM

Write Once, Read Many para requerimientos regulatorios estrictos

¿Qué es S3 Object Lock?

Impide que un objeto sea eliminado o sobrescrito durante un período de retención determinado o de forma indefinida.

Modos de Retención
  • Compliance Mode: Nadie (ni siquiera el Root User) puede eliminar el objeto durante el período.
  • Governance Mode: Usuarios con permisos especiales pueden eludir la retención.
🔒 WORM Model

Objeto Subido ➔ Object Lock Activo ➔ 🚫 Imposible Modificar / Borrar durante el periodo configurado
Slide 23 — Casos de Uso

S3 Static Website Hosting

Alojamiento de contenido web estático de bajo costo

Contenido Estático vs Dinámico

Permitido en S3: Archivos HTML, CSS, JavaScript del cliente, imágenes y videos.

NO Permitido: Scripts del lado del servidor (PHP, Python, Node.js) ni bases de datos dinámicas.

🌐 Navegador ➔ URL de Endpoint S3 ➔ S3 Bucket (index.html + style.css)

Para aceleración global:
Navegador ➔ Amazon CloudFront (CDN) ➔ S3 Bucket
Slide 24 — Integración

S3 + Amazon CloudFront (CDN)

Distribución global con baja latencia y caching en Edge Locations

Beneficios de la Integración
  • Cachea el contenido del bucket en más de 600 Edge Locations en todo el mundo.
  • Reduce la latencia de descarga para usuarios globales.
  • Permite restringir el acceso directo al bucket mediante **Origin Access Control (OAC)**.
👤 Usuario (Chile) ➔ ⚡ Edge Location (Santiago) ➔ 📦 S3 Bucket (us-east-1)
Slide 25 — Integración

S3 Event Notifications + AWS Lambda

Arquitectura orientada a eventos en tiempo real

Caso de Uso Típico

S3 genera un evento automáticametne ante acciones como `s3:ObjectCreated:*`. Este evento desencadena una función **AWS Lambda** para procesar el archivo al instante.

1. Carga foto.jpg en S3 ➔

Slide 26 — Integración Analytics

Amazon S3 como Data Lake

El repositorio centralizado de datos no estructurados y estructurados de AWS

Integraciones Analíticas
  • Amazon Athena: Consulta datos directamente en S3 usando SQL estándar.
  • AWS Glue: Cataloga y realiza procesos ETL sobre datos en S3.
  • Amazon EMR / Redshift Spectrum: Analítica masiva a gran escala.

Slide 27 — Características Avanzadas

S3 Access Points y Presigned URLs

Gestión simplificada de permisos y accesos temporales

S3 Access Points

Puntos de acceso con políticas individuales asignadas a un bucket para simplificar permisos de múltiples aplicaciones.

S3 Presigned URLs

Proporciona acceso temporal a objetos privados sin modificar las políticas del bucket (ej. enlace de descarga válido por 15 minutos).

Slide 28 — Arquitectura Interna

S3 Strong Consistency (Consistencia Fuerte)

Comportamiento actual de S3 para todas las operaciones

Strong Read-After-Write Consistency

Tras una escritura exitosa (PUT) de un objeto nuevo o sobrescritura de uno existente, cualquier lectura posterior (GET) devolverá inmediatamente el valor actualizado.

🎯 Nota de Examen Cloud Practitioner

S3 ofrece **Consistencia Fuerte automática** sin costos adicionales ni cambios de configuración requeridos.

Slide 29 — Conceptos Esenciales

Durabilidad vs Disponibilidad en S3

Garantías del servicio de almacenamiento

💾 Durabilidad (99.999999999%)

Diseñado para **11 nueves** de durabilidad de objetos. Significa que si almacenas 10,000,000 de objetos, se esperaría la pérdida de un solo objeto cada 10,000 años.

⚡ Disponibilidad (99.99%)

Garantía de uptime del servicio para acceder a los datos almacenados a lo largo de un año determinado según la Storage Class.

Slide 30 — Facturación

Factores que Influyen en el Costo de S3

Entendiendo el modelo de pago por uso de S3

Pilares de Cobro
  • Almacenamiento: GBs acumulados por mes.
  • Solicitudes (Requests): Cantidad de operaciones (PUT, GET, LIST).
  • Data Transfer OUT: Transferencia de datos saliente hacia Internet.
  • Recuperación de Datos: Aplica a clases IA y Glacier.
🎯 Regla de Transferencia de Datos

La transferencia de datos **Entrante (Data Transfer IN)** a S3 desde Internet es totalmente **GRATUITA**.

Slide 31 — Repaso Anti-Trampas

⚠️ Mitos y Errores Frecuentes sobre S3

Diferenciación rápida para evitar trampas en el examen

❌ "S3 es un disco duro virtual"
➔ Falso: S3 es almacenamiento de objetos accedido por API, no un sistema de archivos adjuntable a SO.

❌ "Cifrar mi bucket lo hace inaccesible para hackers"
➔ Falso: Cifrado $\neq$ Autorización. Las políticas de IAM/Bucket controlan quién accede.

❌ "Versioning equivale a tener un Backup completo"
➔ Falso: Versioning guarda variantes en el mismo bucket, no es un plan de backup aislado.

❌ "Un bucket privado bloquea incluso las URLs firmadas"
➔ Falso: Las Presigned URLs permiten acceso temporal explícito a objetos privados.

Slide 32 — Evaluación Examen

Pregunta Tipo AWS Cloud Practitioner

Aplica los detectores de palabras clave

Una empresa tiene registros de auditoría que deben conservarse durante 7 años por cumplimiento legal. Los datos casi nunca se consultan y se acepta un tiempo de recuperación de hasta 24 horas. ¿Cuál es la clase de almacenamiento S3 MÁS rentable?

A) S3 Standard-IA
B) S3 Glacier Instant Retrieval
C) S3 Glacier Deep Archive
D) S3 Intelligent-Tiering
¡Respuesta Correcta: C!
Palabra Clave: Retención a largo plazo (7 años), acceso rarísimo, tiempo de recuperación largo $\rightarrow$ **S3 Glacier Deep Archive** ofrece el costo de almacenamiento más bajo de AWS.

Slide 35 — Cierre de la Clase

Si solo recuerdas 12 cosas de S3...

Conceptos fundamentales para aprobar la certificación

  1. S3 es almacenamiento de objetos ilimitado (hasta 5TB por objeto).
  2. Nombres de buckets son globalmente únicos.
  3. Key = Identificador completo de un objeto.
  4. Intelligent-Tiering es para patrones de acceso impredecibles.
  5. Glacier Deep Archive es el almacenamiento más económico de AWS.
  6. Lifecycle automatsa la transición de clases y expiración.
  1. Versioning evita la pérdida accidental por sobrescritura o borrado.
  2. CRR requiere que Versioning esté activado.
  3. Block Public Access está activado por defecto.
  4. Object Lock proporciona inmutabilidad WORM.
  5. 11 nueves (99.999999999%) de durabilidad.
  6. Data Transfer IN hacia S3 siempre es gratis.
