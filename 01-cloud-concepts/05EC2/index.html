Slide 02

¿Qué es Amazon EC2?

Capacidad de cómputo modificable bajo demanda en la nube

🖥️ Infraestructura Tradicional
  • Comprar servidores físicos por adelantado.
  • Semanas de espera para instalación y cableado.
  • Capacidad fija y difícil de modificar.
  • Mantenimiento físico y costos continuos.
☁️ Amazon EC2 (IaaS)
  • Servidores virtuales (instancias) listos en segundos.
  • Paga solo por la capacidad que utilizas.
  • Aumenta o disminuye recursos fácilmente (Elasticidad).
  • AWS administra la infraestructura física subyacente.

🎯 Concepto de Examen

EC2 es un servicio IaaS (Infraestructura como Servicio).


El cliente mantiene control total sobre el Sistema Operativo, configuración de red, seguridad y las aplicaciones que se ejecutan dentro.

Slide 04

Anatomía de una Instancia EC2

Los elementos clave que componen un servidor virtual

💿 AMI

Plantilla que contiene el Sistema Operativo y configuraciones de inicio.

⚙️ Instance Type

Combinación de recursos (CPU, Memoria RAM, Red).

💾 Storage

EBS (Persistente en red) o Instance Store (Efímero en host).

🛡️ Security Group

Firewall virtual que controla el tráfico de entrada y salida.

🔑 Key Pair

Llaves criptográficas para autenticación SSH/RDP segura.

🌐 IP Privada / Pública

Direccionamiento de red dentro de la VPC e Internet.

Slide 05

Almacenamiento: EBS vs Instance Store

Diferencia crítica para el examen Cloud Practitioner

Característica Amazon EBS Instance Store
Ubicación Red (Persistente e independiente) Físicamente unido al host
Al Detener Instancia ✓ Datos Persisten ❌ Datos se pierden
Uso Típico Sistema Operativo, Bases de datos Cachés, Buffers temporales
💡 Clave de Examen

Los volúmenes EBS sobreviven si la instancia se detiene. El almacenamiento Instance Store es efímero y se borra al detener la instancia.

Slide 06

Security Groups (Firewalls Virtuales)

Control del tráfico a nivel de instancia

Reglas Principales
  • Funcionan a nivel de Instancia.
  • Son Stateful: Si el tráfico de entrada se permite, la respuesta sale automáticamente.
  • Solo soportan reglas de ALLOW (Permitir). Deniegan todo por defecto.
Simulador Inbound (Entrante)
Slide 07

Modos de Compra de EC2

Estrategias de optimización de costos en la nube

On-Demand

Pago por segundo/hora sin compromiso. Ideal para pruebas y cargas impredecibles.

Reserved Instances / Savings Plans

Compromiso continuo de 1 o 3 años. Descuentos significativos (hasta 72%).

Spot Instances

Aprovecha capacidad ociosa con hasta 90% de descuento. Puede ser interrumpida por AWS.

Dedicated Hosts

Servidor físico dedicado para cumplir regulaciones estrictas o licencias software (BYOL).

Slide 10

Modelo de Responsabilidad Compartida en EC2

Línea divisoria en Infraestructura como Servicio (IaaS)

☁️ AWS Responsable de (OF the Cloud):
  • Seguridad física de Centros de Datos.
  • Hardware de servidores y discos.
  • Infraestructura de red subyacente.
  • Hypervisor (Nitro) y virtualización base.
👤 Cliente Responsable de (IN the Cloud):
  • Parches y actualizaciones del Sistema Operativo.
  • Configuración de Security Groups / Firewalls.
  • Gestión de acceso (IAM) y datos almacenados.
  • Código y software de la aplicación.
Slide 11

Pregunta Tipo Examen Cloud Practitioner

Aplica los conceptos aprendidos

Una empresa necesita ejecutar un procesamiento por lotes que tolera interrupciones y busca reducir los costos en un 80-90% comparado con el precio bajo demanda. ¿Qué opción debe elegir?

A) Reserved Instances
B) Spot Instances
C) On-Demand Instances
D) Dedicated Hosts
¡Correcto! Las **Spot Instances** ofrecen hasta un 90% de descuento aprovechando capacidad ociosa de AWS, ideales para cargas de trabajo tolerantes a interrupciones.
