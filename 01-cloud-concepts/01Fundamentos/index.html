Sección 05 — Modelo Financiero

CapEx vs. OpEx: Cambio de Modelo Económico

Mueve el control para comparar la estructura de costos On-Premises frente a Cloud

Modelo Tradicional (CapEx Dominante) Modelo Cloud (OpEx Dominante)
🏛️ CapEx (Capital Expenditure)

Inversión de capital inicial significativa en activos físicos.

  • Compra de servidores físicos y storage
  • Construcción/alquiler de data center
  • Contratos de energía y refrigeración a largo plazo
  • Inversión fija de alto riesgo previo a la demanda
⚡ OpEx (Operational Expenditure)

Gastos operativos variables según la actividad del negocio.

  • Sin costo inicial de infraestructura
  • Pago por uso variable según consumo real
  • Flexibilidad para cancelar recursos en cualquier momento
  • Escalabilidad alineada directamente con los ingresos

Sección 11 — Modelos de Despliegue

Nube Pública, Privada e Híbrida

Tres formas de desplegar y operar la infraestructura

🌐 Nube Pública

Propiedad de un proveedor cloud (AWS) que ofrece recursos a múltiples clientes a través de Internet.

Ej. Amazon EC2, S3
🔒 Nube Privada

Infraestructura utilizada exclusivamente por una sola organización (On-Premises o Data Center dedicado).

Control absoluto / Mayor costo
🔀 Nube Híbrida

Conecta infraestructura On-Premises local con recursos de la Nube Pública de forma integrada.

Ej. AWS Direct Connect / VPN
Sección 12 — AWS Global Infrastructure

Regiones y Availability Zones (AZs)

La base física global sobre la que se construyen los servicios de AWS

🌍 Región de AWS

Ubicación geográfica física en el mundo que agrupa múltiples Zonas de Disponibilidad aisladas (Ej. us-east-1 N. Virginia).

Factores para elegir una Región:

  • Cumplimiento y Residencia de Datos: Leyes locales.
  • Latencia: Cercanía física a los usuarios finales.
  • Disponibilidad de Servicios: Servicios habilitados.
  • Costo: Precios variados según el país/región.
🏢 Availability Zone (AZ)

Uno o más centros de datos físicos discretos con energía, red y refrigeración redundantes dentro de una Región.

Sección 14 — Mitos Frecuentes

Mitos vs. Realidades de Cloud Computing

Desmontando confusiones comunes para la certificación AWS

❌ Mito: "La nube no utiliza servidores físicos."

Realidad: La nube se apoya completamente en servidores físicos, discos y data centers reales administrados por el proveedor.

❌ Mito: "Migrar a la nube siempre es más barato automáticamente."

Realidad: Cloud cambia el modelo de cobro. Si no se optimizan los recursos, puede resultar costoso. El ahorro proviene de la elasticidad y el correcto dimensionamiento.

❌ Mito: "Todo escala automáticamente en la nube sin configurar nada."

Realidad: Debes diseñar y configurar servicios como AWS Auto Scaling y Load Balancers para lograr elasticidad.

❌ Mito: "AWS se encarga de la seguridad de mis datos y contraseñas."

Realidad: Bajo el modelo de responsabilidad compartida, el cliente es responsable del cifrado, los datos y los permisos de acceso de usuarios.
