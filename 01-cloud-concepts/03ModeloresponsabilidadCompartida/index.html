🛡️ AWS Cloud Practitioner: Responsabilidad Compartida
Sección 01 — Introducción

Modelo de Responsabilidad Compartida de AWS

En AWS, la seguridad y el cumplimiento normativo son una responsabilidad compartida entre AWS y el cliente.

☁️ AWS: Security OF the Cloud

AWS es responsable de proteger la infraestructura física, hardware, centros de datos y software base que ejecuta los servicios en la nube.

👤 Cliente: Security IN the Cloud

El cliente es responsable de la configuración, datos, gestión de acceso (IAM), parches del SO (según servicio) y seguridad de sus aplicaciones.

Sección 03 — Responsabilidad de AWS

Security OF the Cloud (Seguridad DE la Nube)

AWS gestiona la infraestructura global y los componentes de hardware/software base

🏢 Componentes gestionados por AWS
  • Centros de datos físicos: Edificios, controles biométricos, guardias de seguridad y generadores de energía.
  • Hardware de cómputo y almacenamiento: Servidores físicos, discos duros, switches y cables de fibra.
  • Infraestructura de red subyacente: Enrutamiento global y atenuación de ataques volumétricos.
  • Hypervisor de virtualización: Capa de aislamiento (ej. AWS Nitro) que separa las máquinas virtuales.

Sección 04 — Responsabilidad del Cliente

Security IN the Cloud (Seguridad EN la Nube)

El cliente controla lo que almacena, quién accede y cómo configura sus servicios

👤 Control y Configuración del Cliente
  • Datos del cliente: Cifrado de datos en reposo y en tránsito.
  • Gestión de Identidad (IAM): Creación de usuarios, contraseñas, MFA y permisos (Principio de Menor Privilegio).
  • Configuración de red (VPC): Tablas de enrutamiento, Security Groups y Network ACLs.
  • Sistema Operativo Invitado: Parches de seguridad e instalación de software en instancias EC2.

      Amazon RDS: Base de Datos Relacional Administrada

      AWS parchea el motor y el SO; el cliente gestiona los datos, usuarios y esquemas

      ☁️ Lo que AWS Administra en RDS
      • Instalación y mantenimiento del hardware de BD.
      • Parches del Sistema Operativo base.
      • Parches del motor de base de datos (MySQL/PostgreSQL).
      • Copias de seguridad automáticas (Backups) y Multi-AZ.
      👤 Lo que el Cliente Administra en RDS
      • Diseño de tablas, esquemas y optimización de consultas SQL.
      • Creación y permisos de usuarios de la base de datos.
      • Cifrado de datos y credenciales de conexión.
      • Reglas de tráfico de red (Security Groups asociados).
      Sección 09 — Caso Serverless

      AWS Lambda: Cómputo sin Servidores

      Serverless NO significa sin servidores; significa que AWS los administra por ti

      ⚡ Abstracción Total de Infraestructura

      En AWS Lambda, no hay instancias EC2 ni sistemas operativos que configurar o parchear.

      • AWS administra: Servidores, SO, runtime (NodeJS/Python), escalado y capacidad.
      • El cliente administra: El código de la función, las dependencias, la configuración de memoria y los permisos de ejecución IAM.

      Sección 11 — Identidad y Accesos

      IAM: Responsabilidad Absoluta del Cliente

      AWS provee la herramienta IAM; el cliente es responsable de configurarla correctamente

      🔐 Prácticas Recomendadas del Cliente
      • Autenticación Multi-Factor (MFA): Obligatoria en la cuenta Root y usuarios IAM.
      • Principio de Menor Privilegio: Otorgar únicamente los permisos necesarios para realizar una tarea.
      • Uso de Roles de IAM: Asignar roles a instancias EC2 en lugar de guardar claves hardcodeadas en el código.
      • Rotación de credenciales: Cambiar periódicamente claves de acceso y contraseñas.
      ⚠️ Protección de la Cuenta Root

      La cuenta Root tiene acceso sin restricciones a todos los recursos y facturación.

      📌 Regla de Examen: Bloquea la cuenta Root con MFA, no crees claves de acceso para Root y utiliza usuarios/roles de IAM para tareas cotidianas.
      Sección 12 — Protección de Datos

      Cifrado de Datos y AWS KMS

      AWS proporciona el servicio de claves (KMS); el cliente decide qué y cómo cifrar

      🔒 Cifrado en Reposo (At Rest)

      Proteger los datos guardados en discos EBS, buckets S3 o bases de datos RDS.

      El cliente debe habilitar la casilla de cifrado e integrar llaves de AWS KMS (Key Management Service).

      🌐 Cifrado en Tránsito (In Transit)

      Proteger los datos mientras viajan por la red entre clientes y servidores.

      El cliente debe configurar protocolos seguros como TLS/HTTPS y gestionar certificados mediante AWS Certificate Manager (ACM).

      Sección 14 — Mitos Frecuentes

      Desmontando Mitos de la Nube

      Aclarando malentendidos habituales en las preguntas de certificación

      ❌ MITO 1: "AWS se encarga de toda la seguridad porque está en la nube."

      Realidad: AWS solo protege la infraestructura base. Si dejas un bucket S3 público o contraseñas débiles, la falla es 100% responsabilidad del cliente.

      ❌ MITO 2: "Usar un servicio administrado (ej. RDS) elimina mis tareas de seguridad."

      Realidad: AWS elimina la gestión de parches del SO, pero tú sigues siendo responsable de los usuarios, contraseñas, permisos y datos de la base de datos.

      ❌ MITO 3: "Serverless significa que no hay responsabilidad de infraestructura."

      Realidad: Los servidores existen y los administra AWS, pero el cliente sigue siendo responsable de la seguridad del código y las dependencias de la función.

      ❌ MITO 4: "AWS decide quién tiene acceso a mis archivos guardados en S3."

      Realidad: El cliente mantiene la soberanía absoluta de sus datos y configura explícitamente las políticas de acceso IAM y de bucket.

      Sección 18 — Síntesis Final

      Resumen para el Examen Cloud Practitioner

      Si solo recuerdas 5 cosas antes de rendir el examen, que sean estas:

      • 🛡️ AWS es responsable de la seguridad DE la nube (Data Centers, Hardware físico, Hypervisor, Red base).
      • 👤 El CLIENTE es responsable de la seguridad EN la nube (Datos, Gestión de Identidades IAM, Cifrado, Configuración de Firewalls).
      • ⚙️ En EC2 (IaaS), el cliente DEBE actualizar y parchear el Sistema Operativo Invitado.
      • 📦 En RDS / Lambda / S3, AWS asume los parches del SO/Runtime, pero el cliente MANTIENE la responsabilidad de datos y accesos.
      • 🔑 La protección de la Cuenta Root con MFA y el principio de menor privilegio en IAM son responsabilidad 100% del cliente.
