Bloque 1: El Problema Empresarial

Una plataforma de comercio electrónico procesa cientos de pedidos al día. Su equipo de soporte técnico recibe reportes frecuentes de fallos en compras, pero analizar la causa toma horas.

Actualmente, los operadores revisan archivos de registros (logs) de forma manual. Un extracto típico luce así: 

2026-10-12 08:15:22|INFO|auth_service|Usuario inicio sesion exitosamente.
2026-10-12 08:17:10|ERROR|payment_gateway|Fallo en la conexion con la pasarela de pagos.
2026-10-12 08:20:12|INVALID_LOG_ENTRY_WITHOUT_DELIMITERS

Pregunta de reflexión:

¿Qué problemas identificas al analizar miles de líneas como estas manualmente?

Análisis: El proceso manual es lento, propenso a errores humanos, no detecta registros corruptos fácilmente y no permite agrupar fallos por componente crítico para tomar decisiones operativas inmediatas.

Bloque 2: Pensar Antes de Programar

Algoritmo en Lenguaje Natural:

  1. Abrir y leer el archivo de registros línea por línea.
  2. Comprobar si la línea tiene exactamente 4 campos separados por el carácter |.
  3. Si es inválida, incrementar el contador de errores de formato y continuar.
  4. Si es válida, clasificar por severidad (INFO, WARNING, ERROR).
  5. Si es un ERROR, contabilizar el componente de software afectado y el mensaje.
  6. Escribir las métricas calculadas en un archivo estructurado results.txt.

Bloque 3.1: Python Básico - Listas y Cadenas

Para manipular texto en Python, utilizamos el método split() de las cadenas de texto (strings). Este divide una cadena en partes separadas por un delimitador, devolviendo una lista. 

# Ejemplo mínimo
linea = "2026-10-12|ERROR|payment_gateway|Timeout en la respuesta"
campos = linea.split("|")

print(campos[1])  # Resultado: "ERROR"
print(len(campos)) # Resultado: 4

Desafío rápido: Si ejecutamos "A|B".split("|"), ¿cuántos elementos tendrá la lista resultante?

Bloque 3.2: Contadores con Diccionarios

Un diccionario guarda información en pares de clave-valor. Es la herramienta ideal para agrupar y contar elementos dinámicamente (como errores por componente). 

# Inicializar diccionario de conteo
errores = {}
componente = "payment_gateway"

# Patrón de acumulación
if componente in errores:
    errores[componente] += 1
else:
    errores[componente] = 1

print(errores) # Output: {'payment_gateway': 1}

Este patrón nos permite registrar componentes nuevos sin necesidad de conocer sus nombres de antemano.

Bloque 4: Construcción del Programa (`main.py`)

El programa principal se estructura en funciones pequeñas con responsabilidad única: 

def validar_y_extraer_registro(linea):
    linea_limpia = linea.strip()
    if not linea_limpia:
        return None
    campos = linea_limpia.split("|")
    if len(campos) != 4:
        return None  # Registro mal formado
    return [campo.strip() for campo in campos]

Manejo preventivo de errores: Si un registro no tiene exactamente 4 campos (como un log incompleto o corrupto), la función retorna None. El programa no se interrumpe y registra la falla en la estadística de registros inválidos.

Bloque 6.1: Conexión con AWS Cloud Practitioner

En un entorno local, nuestro programa procesa un archivo estático. En una arquitectura en la nube con AWS, esta solución evoluciona hacia una infraestructura automatizada y escalable.

App E-Commerce
Genera Logs
→
Amazon S3
Almacenamiento Objeto
→
AWS Lambda
Procesa con Python
→
Amazon CloudWatch
Monitoreo y Alertas
  • Amazon S3: Almacena archivos de logs de manera highly disponible y duradera.
  • AWS Lambda: Ejecuta el código Python automáticamente cada vez que se sube un nuevo archivo de log a S3 (serverless, sin gestionar servidores).
  • Amazon CloudWatch: Recopila métricas de ejecución y activa alarmas si los eventos de nivel ERROR superan un umbral.

Bloque 6.2: Dominios de Certificación AWS

  • Conceptos de la Nube: Tareas que antes requerían servidores encendidos 24/7 para procesar datos se convierten en cómputo Serverless (pago por uso exacto y escalabilidad automática).
  • Seguridad (Modelo de Responsabilidad Compartida): AWS asegura la infraestructura subyacente de Lambda y S3. El usuario es responsable de configurar los permisos IAM adecuados (Principio de Mínimo Privilegio) para que Lambda solo lea del bucket de logs autorizado.
  • Facturación y Precios: AWS Lambda no cobra por tiempo de inactividad, lo que optimiza significativamente los costos operativos comparado con mantener una máquina virtual (Amazon EC2) fija.

Bloque 7: Desafío Práctico

Enunciado: La gerencia requiere que el programa identifique automáticamente cualquier componente que acumule 3 o más errores y añada una sección dedicada de ALERTAS CRÍTICAS en el archivo results.txt.

Criterios de Aceptación:

  • Filtrar el diccionario de errores por componente.
  • Si un componente tiene ≥ 3 errores, incluirlo en la alerta.
  • Probar que en nuestro caso de ejemplo, payment_gateway (4 errores) genere la alerta e inventory (2 errores) no. 
# Código de referencia para añadir al informe:
f.write("6. ALERTAS CRÍTICAS DE INFRAESTRUCTURA\n")
f.write("----------------------------------------------------\n")
hay_alertas = False
for comp, cant in resumen['errores_por_componente'].items():
    if cant >= 3:
        f.write(f"¡ALERTA!: El componente '{comp}' requiere atención (Errors: {cant})\n")
        hay_alertas = True
if not hay_alertas:
    f.write("No se registraron componentes críticos con alto volumen de fallos.\n")
