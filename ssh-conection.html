SSH = Secure Shell
Fundamentos del protocolo
Concepto

"Protocolo que permite conectarse de forma segura a otro equipo a través de una red."

MI COMPUTADOR (Windows / Linux / macOS) │ │ SSH (Cifrado) ▼ INTERNET │ ▼ AWS │ ▼ EC2 Linux
📌 Concepto Clave: SSH utiliza normalmente el puerto de transporte TCP 22 para establecer comunicaciones cifradas.

El firewall virtual a nivel de instancia

Pregunta Interactiva: ¿Qué controla principalmente un Security Group?

Explicación Correcta (B): Un Security Group funciona como un firewall virtual que filtra el tráfico a nivel de red/instancia antes de que alcance el sistema operativo.

🛡️ Regla de Oro: La clave privada (.pem / .ppk) NUNCA debe compartirse ni subirse a repositorios públicos.
Windows: PuTTY
Cliente SSH con interfaz gráfica (GUI)
Windows GUI

PuTTY utiliza un formato de clave propietario denominado .ppk.

.pem (Clave AWS) ──► PuTTYgen (Conversor) ──► .ppk ──► PuTTY ──► EC2

Explicación: PuTTYgen es la herramienta incluida junto con PuTTY que permite importar el archivo .pem otorgado por AWS y convertirlo a un archivo .ppk reconocible por PuTTY.

Configurar PuTTY
Representación visual de la interfaz
Configuración
1. Configuración de Sesión
Host Name: PUBLIC_DNS (o ec2-user@PUBLIC_DNS) Port: 22 Connection type: SSH
2. Adjuntar Clave Privada (.ppk)
Categoría Lateral: Connection ➔ SSH ➔ Auth ➔ Credentials Private key file: Select "my-key.ppk"
Windows: PowerShell / OpenSSH
Conexión por línea de comandos nativa
Windows CLI
ssh -i "my-key.pem" ec2-user@PUBLIC_DNS
ssh: Comando cliente OpenSSH.
-i: Indica que se especificará un archivo de identidad (clave).
my-key.pem: Ruta a la clave privada.
ec2-user: Usuario del sistema Linux.
PUBLIC_DNS: Dirección pública de la instancia EC2.
Linux: Terminal + OpenSSH
Permisos de clave y ejecución
Linux
Paso 1: Proteger permisos de la clave
chmod 400 my-key.pem

OpenSSH exige estrictamente que la clave privada no sea accesible por otros usuarios locales.

Paso 2: Conectarse a EC2
ssh -i "my-key.pem" ec2-user@PUBLIC_DNS
[ec2-user@ip-10-0-1-50 ~]$ # ¡Estamos dentro de la instancia EC2 Linux!
macOS: Terminal + OpenSSH
Conexión nativa en Mac
macOS
chmod 400 my-key.pem ssh -i "my-key.pem" ec2-user@PUBLIC_DNS
Mac ──► Terminal ──► OpenSSH ──► Internet ──► AWS ──► EC2

El flujo en macOS es conceptual y prácticamente idéntico al de Linux.

Troubleshooting: No puedo conectarme
Ruta de diagnóstico por capas (Usa → o haz clic)
Diagnóstico
1. ¿Llego a EC2? (Capa de Red)

Si NO: Revisar Security Group (TCP 22), IP pública, conectividad a Internet o estado de la EC2.

2. ¿Me autentico? (Capa de Autenticación)

Si NO: Revisar nombre de usuario (ej: ec2-user vs ubuntu), clave privada seleccionada o permisos del archivo (chmod 400).

Interpretación de Errores Básicos
Mensajes comunes y significado
Errores
Connection timed out

Revisar: Security Group, puerto TCP 22 bloqueado, IP pública incorrecta.

Permission denied (publickey)

Revisar: Clave privada incorrecta, usuario incorrecto, permisos de archivo laxos.

Could not resolve hostname

Revisar: Hostname o DNS mal escrito, falta de resolución DNS local.

Connection refused

Significado: Instancia alcanzable, pero el servicio SSH (sshd) no está escuchando.

SSH + Buenas Prácticas de Seguridad
Reglas para el examen y producción
Seguridad

🔐 Proteger .pem y .ppk: Mantener las claves privadas seguras.
🚫 No compartir claves privadas: Tratarlas como credenciales secretas.
🎯 Restringir el puerto 22: Limitar el origen en Security Group a tu IP.

⚠️ Evitar 0.0.0.0/0: No dejar SSH abierto a todo Internet de forma permanente.
👤 Utilizar usuario correcto: Usar usuarios estándar de la AMI.
☁️ Security Groups: Usarlos para controlar todo tráfico de red.
