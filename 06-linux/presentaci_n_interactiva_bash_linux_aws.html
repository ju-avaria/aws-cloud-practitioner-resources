    ¿Qué es una Shell?

    Aclarando los tres conceptos fundamentales que suelen confundirse al comenzar.

    🖥️ Terminal vs 💻 Shell

    Terminal: Es la ventana o programa gráfico que te permite escribir e interactuar con la línea de comandos.

    Shell: Es el intérprete de comandos interno. Recibe las instrucciones escritas y las traduce para que el kernel de Linux las ejecute.

    ⚡ ¿Qué es Bash?

    Bash (Bourne Again SHell) es un tipo específico de Shell, estándar en la mayoría de las distribuciones Linux.

    ⚠️ Importante: Bash forma parte del sistema operativo Linux. No es un servicio nativo de AWS.

    Analogía: Terminal = Pantalla y Teclado | Shell (Bash) = Traductor | Linux = El Motor

    De un Comando a un Script

    Comparación entre la ejecución manual interactiva y la automatización por archivos.

    Ejecución Manual

    Escribir cada comando individualmente en la terminal:

    $ date $ whoami $ pwd

    ❌ Lento, tedioso y propenso a errores al repetirlo en múltiples servidores.

    Ejecución Automatizada (Script)

    Guardar todas las órdenes en un archivo como diagnostico.sh:

    date whoami pwd

    ✅ Rápido, consistente y reusable en cualquier momento.

    Un Script Bash es un archivo de texto con instrucciones consecutivas que la Shell ejecuta en orden.

    Anatomía de un Script Bash

    Analicemos la estructura de un script básico línea por línea:

    #!/bin/bash # 1. Shebang: indica el intérprete a utilizar echo "Hola, Linux" # 2. Imprime un texto en consola date # 3. Muestra la fecha/hora del sistema whoami # 4. Muestra el usuario activo

    Línea Fundamental: El Shebang (#!/bin/bash)

    Comienza con los caracteres #! seguidos de la ruta del ejecutable de Bash (/bin/bash). Le indica al sistema operativo qué programa debe interpretar el contenido del archivo.

    Crear y Ejecutar un Script

    Los pasos necesarios para poner en marcha un archivo ejecutable en Linux:

    Método 1: Ejecución Directa

    Requiere otorgar permisos explícitos de ejecución:

    chmod +x saludo.sh ./saludo.sh

    chmod +x añade el permiso de ejecución. El prefijo ./ le indica al sistema que el archivo se encuentra en el directorio actual.

    Método 2: Llamada con el Intérprete

    Invocando directamente al programa Bash:

    bash saludo.sh

    No exige que el archivo tenga permisos de ejecución activos, únicamente permisos de lectura.

    Comandos Linux Frecuentes dentro de Bash

    Instrucciones básicas utilizadas frecuentemente en scripts de administración y diagnóstico:

    Comando Descripción Salida Representativa Caso de Uso
    pwd Muestra la ruta del directorio actual /home/ec2-user Validar la ubicación antes de crear o mover archivos.
    whoami Muestra el usuario efectivo actual ec2-user / root Verificar el nivel de privilegio de la sesión.
    date Muestra la fecha y hora del sistema Mon Oct 12 21:00:00 UTC Agregar registros de auditoría o marcas de tiempo.
    ls Lista archivos y directorios saludo.sh logs/ Comprobar si existen archivos requeridos.
    df -h Muestra uso del espacio en disco /dev/xvda1 20G 3.2G (16%) Auditar el almacenamiento disponible de forma legible.
    free -h Muestra el estado de la memoria RAM Mem: 1.0Gi 240Mi libre Comprobar la memoria disponible en el servidor.

    Variables y Mensajes en Bash

    Las variables permiten almacenar datos para reutilizarlos fácilmente en todo el script.

    #!/bin/bash servidor="EC2-Linux" echo "Diagnóstico del servidor: $servidor"

    Reglas Clave al Definir Variables:

    • Sin espacios: La asignación no debe llevar espacios en torno a = (ej: servidor="EC2-Linux").
    • Lectura con $: Se añade el prefijo $ para invocar su valor (ej: $servidor).
    • Comillas dobles: Permiten la interpretación de variables dentro de cadenas de texto.
    Salida obtenida: Diagnóstico del servidor: EC2-Linux

    Ejecución Secuencial Paso a Paso

    Bash procesa el código línea por línea, de arriba a abajo, de forma estricta.

    Código del Script

    #!/bin/bash
    echo "=== Diagnóstico básico ==="
    date
    whoami
    pwd

    Intérprete & Scripts

    Relación de Conceptos:

    • Amazon EC2: Ofrece la capacidad de cómputo en la nube (la máquina virtual).
    • Linux: Es el sistema operativo de la instancia.
    • Bash: Es la shell utilizada para administrar el sistema interno.

    💡 Aplicación Práctica: EC2 User Data

    Al lanzar una instancia en AWS, se puede definir un Script Bash en la sección User Data para instalar automáticamente dependencias, paquetes y aplicaciones durante el primer arranque.

    Caso Práctico: Script de Diagnóstico

    Uso de sustitución de comandos mediante la sintaxis $(comando):

    #!/bin/bash echo "=== Diagnóstico del servidor ===" echo "Fecha: $(date)" echo "Usuario: $(whoami)" echo "Directorio: $(pwd)" echo "=== Espacio en disco ===" df -h echo "Diagnóstico finalizado"

    Explicación Técnica:

    La expresión $(comando) evalúa la instrucción contenida dentro del paréntesis y sustituye su valor dinámicamente antes de enviar la salida al comando echo.

    Errores Habituales y Buenas Prácticas

    Recomendaciones esenciales para la escritura de scripts seguros y funcionales:

    ❌ Errores Frecuentes

    • Espacios en variables:
      servidor = "EC2" # Error
    • Ejecutar archivos directamente sin añadir permisos previos con chmod +x.
    • Confundir comandos internos del SO Linux con comandos de la AWS CLI.

    ✅ Buenas Prácticas

    • Asignación limpia:
      servidor="EC2" # Correcto
    • Incluir siempre el Shebang correspondiente al inicio del script.
    • 🛡️ Seguridad Cloud: Jamás escribir contraseñas ni claves de acceso AWS en texto plano. Usar servicios dedicados como AWS Secrets Manager.
